# Changelog

## [0.7.0] - 2026-10-07

20 commits since v0.6.1.

### Added

- **Parquet and DuckDB files as inputs**: `.parquet` files and `.duckdb` database files can now be opened as tabs and feed the pipeline, alongside CSV. A `.duckdb` file asks which table to read. Nothing is bundled to make this work — the DuckDB CLI plugin you already install reads the files directly, so column types (decimals, timestamps) survive instead of round-tripping through CSV text. The pipeline decides per run: if the first consuming step is a `duckdb` step, the original file is handed to it untouched; otherwise the input is materialized once to CSV and the rest of the run is unchanged. Chained `duckdb` steps are stitched into a single SQL script and run in one process with no intermediate files at all; only when an `xan` step sits between two `duckdb` steps is a temporary parquet hand-off written. Every CSV path — the contract, delimiter detection, sessions, script export — is untouched. Design `024_parquet-duckdb-file-reading`.
- **Excel multi-file merge**: a new File-level dialog (not a pipeline node) merges sheets out of many workbooks, across folders and recursively, into one table. It picks the first sheet, all sheets, or sheets by name; aligns columns by union by default and reports where a column was widened; can keep a source column naming each row's origin; writes atomically so a failed merge never leaves a half-written file; and remembers the last run's settings. Values are read through the existing `xan`/calamine stack, so nothing new has to be trusted with your data — the layout library `xl` was measured and rejected after it silently turned numbers into dates. Memory stays flat while concatenating (131 MB in, 8.5 MB peak) and peak cost tracks the largest single sheet, not the total, so merging more files does not cost more memory. Design `025_excel-multi-file-merge`.
- **Excel merge output shapes**: the merge dialog now offers four shapes instead of one. **A** merge everything into a single table (the previous behaviour, still the default); **B** one output file per sheet name, merging each workbook's `s1` into `s1.xlsx` and so on — you tick exactly which sheets to emit, so ticking one produces one file; **C** one multi-sheet workbook, one sheet per source workbook named after its file, for a summary you can hand to someone; **D** split a multi-sheet workbook into one file per sheet. Shapes B and D reuse the whole existing pipeline and guarantee "no half-written file" per output; C is the one place a new writer was needed, since `xan to xlsx` can only ever produce a single sheet — so `rust_xlsxwriter` was added for that, a deliberate, bounded exception to the "no new dependencies for one format" rule (the read side still has no new dependency). Sheet names and file names are sanitized against Windows reserved names and the 31-character, case-insensitive sheet-name rules. Default output names now carry a run timestamp so repeated runs stop overwriting each other, and the dialog explains the selected shape with a live example. Designs `026_excel-merge-output-shapes` (extends `025`).
- **First-run onboarding**: a new install is no longer a blank canvas. The app ships a small built-in sample (219 sales rows, including a few empty values and a couple of duplicate rows, so cleaning has something to do) and five ready-made templates (clean up, inspect, group-and-count, sort-and-take-top-100, plus the sample pipeline). **View example** (also in Help → View Example, `Alt+C`) replays a working three-step pipeline **one step at a time**: each click adds the next node together with a caption saying where that step comes from (`2/3 · click dedup → remove fully duplicated rows`), and once the last step is in place the button becomes "run it". There is no timer — the pace is yours — and no fixed number of replays: clicking it again always replays the demo. Skipping completes the pipeline and runs it immediately. New nodes fade in when they are added, so a click visibly does something. The guide state can be reset from Settings. Design `027_first-run-onboarding`.
- **Independent execution per tab**: running a pipeline in one tab no longer locks the others. Each run gets its own session id, so tab A can keep running while you edit tab B and start its run; **Cancel only stops the tab you started it from**, where it used to kill every running tab; and progress, results, logs, charts and dialogs are all routed to the tab that owns them instead of overwriting each other. The concurrency limit defaults to 4 and is adjustable (1–16) in Settings. The Execute button became a small tab menu — the current tab on top, other tabs below, and a row in flight offers only Cancel. Designs `028_multi-tab-concurrent-execution` (and the per-tab result-preview isolation recorded in `027`).
- **Chart readability rework**: the charting panel was rebuilt so charts say what they mean. CSV is now parsed by Rust instead of in JavaScript, which fixes quoted commas, embedded newlines and escaped quotes, and applies a visible 50 000-row cap with a notice rather than silently truncating. Non-numeric values are no longer treated as zero — thousands separators parse correctly and affected rows are skipped with a count instead of dragging a line to the baseline, where they used to make charts look plausible but wrong. A missing column now shows an error card listing the columns that do exist. Legends and tooltips are shared across all seven chart types (single-series charts now get a legend too), bars/pies/heatmaps default to descending order with a three-state sort control, axes use compact numbers while tooltips show full thousands, and the word cloud is laid out deterministically instead of at random. The data-table view scrolls with the app's own scrollbar: wide tables finally scroll sideways, and a legend with many categories stays on one line and can be filtered. Exports always produce a light-background document palette, so charts pasted into a report stay readable. Design `029_chart-readability`.

### Changed

- **Toolbar rebuilt into File / Edit / View / Help menus**, with a search box to find commands on the canvas instead of hunting through the command palette. Settings is now an icon-only button on the far right. Designs referencing the old top-bar zones were updated accordingly.
- **"Check for updates" now shows that it is working**: the Help button carries the same 2px indeterminate bar as a running pipeline while a check is in flight, which previously looked like nothing happened on a slow network. The button stays clickable so you can still open Help mid-check; only the menu item itself is greyed out to prevent a second check.
- **File dialogs redesigned**: the CSV encoding dialog is now a step-by-step layout instead of one dense form; the split-into-good/bad-rows dialog was rebuilt and its scrolling fixed; and the split-by-line-count dialog follows the same pattern, defaulting to 1,000,000 rows per file with the body scrolling correctly. Design `017_separate-dialog-ux` was updated to match.
- **Plugin install button no longer shows a download icon**, which suggested a browser download rather than an in-app install.

### Fixed

- **Plugin manager icon buttons are now properly labelled** for screen readers and automation, so their accessible names match what they do.

### Docs

- Design documents `024`–`029` added, `017` and `022` updated, and `docs/AI/INDEX.md` refreshed for the new modules, commands, data paths and test conventions (including the per-tab execution model and the React `act` environment note from `029`).
