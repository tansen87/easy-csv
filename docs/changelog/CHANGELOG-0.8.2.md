# Changelog

## [0.8.2] - 2026-11-14

5 commits since v0.8.1.

### Added

- **DuckDB SQL autocomplete is anchored to the word being typed** (prototype `051`). The list used to hang under the bottom edge of a 240–400px editor, so after two lines of SQL it opened out of view and you had to scroll the dialog to read it. It now opens at the caret — measured through the same mirror element that draws the highlight — **flips above the word** when the editor's bottom is close, and stays inside the dialog's scroll viewport rather than the window. It is 420px wide and 3–6 **whole** rows tall (28px each, never a half row), scrolling internally past that, and the highlighted row is kept in view as `↑↓` walk past the visible rows. Each row carries a quiet three-letter kind code in the first column — `col` / `fn` / `kw` / `tbl` — instead of the old coloured pills, the typed prefix is the only coloured part of the name, and a function's signature sits right-aligned in monospace. Matches are ranked by kind rather than by vocabulary order: **columns first** (typing a column name is the common case in a `GROUP BY` or a `SELECT` list), then functions, keywords and table functions, with shorter names first inside a kind; the list holds 40 matches instead of 12. A 32px footer names the highlighted row's kind and description (`函数 · Returns the number of rows`) and shows the three keys that do something (`↑↓` `Tab` `Esc`). When a word of two or more characters matches nothing the popover stays put and says so — `无匹配 「foo」` — instead of disappearing, which used to read as the popover being broken; `Esc` dismisses the popover only, so a second `Esc` still closes the dialog.

- **Command palette rebuilt as a search that ranks** (design `053`). The 97-entry list was filtered with a plain `includes` and kept array order, so typing `fi` left `filter` behind 26 actions, groups still sectioned the results while you were searching, and identical-looking rows (`filter` / `fill` / `batch-filter`) gave no hint which one matched. The panel is now 560px with a `›` prompt, a monospace query line and a live `hits / available` count on the right (available already subtracts disabled entries, so "26 actions, 24 results" has an answer). An empty query still browses by group — 操作 / 标签页 / 最近文件 / 模板 / 命令 — with a monospace count after each group name; **the moment you type, grouping is dropped** and everything is sorted into one column by score, with the source pressed into a 10px right-hand label where the keycap used to be. Scoring is **exact label 100, label prefix 80, label contains 60, pinyin initials 55, description/keywords/shortcut/group 30**, ties broken by source (action → command → tab → recent file → template) and then by original order — commands before files on purpose, since what you look for in a *command* palette is usually a command. Pinyin initials come from a generated 711-character table (`utils/pinyinInitials.ts`, built by `scripts/gen-pinyin-initials.mjs` from the zh strings and command data), so `dk` finds 打开文件 with no runtime dependency; characters the table lacks are skipped, which can only lose a match, never invent one. Only the matched run of characters is coloured — brand colour plus 600 weight on a label because colour alone is not enough at 13px, grey→ink on a description — with no background tint, no underline. The transparent `↵` every unselected row used to reserve is gone, `↑↓` now wraps instead of clamping, `Enter` during IME composition no longer fires, and the pointer takes over selection only when it actually moves: `mouseenter` used to arrive while the keyboard still owned the list, so you had to cross a second row before the mouse responded. Empty results explain themselves (`没有匹配「xx」的入口`, plus a line suggesting `filter`, 去重 or an initials search) and the footer drops to `esc 关闭`.

- **The Execute dropdown became a run panel grouped by state** (prototype `052`, superseding the row model in design `028` §5.6.2). It is 240px wide and lists tabs under **运行中 / 排队 / 待确认 / 空闲** headings with counts, instead of one current tab and a divider. Clicking a row now only **switches to that tab**; every action lives in a trailing button — **执行 / 停止 / 处理** — so a click never means two different things depending on state. State is read from a 7px lamp and a monospace readout (branch progress, or `失败`) rather than a coloured pill, the current tab is pinned first inside whichever group it belongs to and carries the 2px left rail, and the footer states the concurrency limit (`最多同时 4 个`) beside the `Ctrl+R` keycap so queueing is explained. The panel is portalled to `document.body`: inside the title bar, its empty rows and footer inherited `data-tauri-drag-region="deep"`, so dragging or double-clicking them moved or maximised the window instead of acting on the panel. A 6px dot after the 「执行」 label appears while another tab is running, queued or waiting, so the panel does not have to be open to know something is in flight.

- **All five menus share one shell and one keyboard** (prototype `054`). The dropdowns widen with their content instead of being pinned at 180px (`min 208` / `max 268`), with a 10px radius, 6px padding and a 6px offset from the trigger; rows use `px-2.5` and, importantly, **foreground-coloured labels** — they were all muted, which made every menu read as half-disabled, with only genuinely disabled items dropping to 40% (keycap included, via `group-disabled`). Hover is an 8% ink tint, separators are an inset hairline with no group headings, and the sections are now File 3+3, View `命令面板 ｜ 4 个开关 ｜ 搜索` and Tools `5 + 2`. An open trigger keeps its ink text over a 12% tint — it used to switch to `bg-accent` + `text-foreground` and lose the brand colour the moment you clicked it — and 「查看」 gains a 12px underline when a panel it controls is open, a separate signal from "this menu is open". `↑↓` / `Home` / `End` move between items and skip disabled ones, `Esc` closes and hands focus back to the trigger (`data-menu-trigger`), and all five now carry `role="menu"` with `aria-haspopup` / `aria-expanded`.

### Changed

- **Tool menu entries are named verb + object**, dropping the `CSV` prefix that the menu itself already implies: 对比差异, 转换编码, 拆分坏行, 按行数拆分, 组内编号 ｜ 转为 Excel, 合并工作簿. The encoding dialog gained a one-line hint (`把文件从一种字符编码转成另一种`) which the command palette uses as its description — it had been repeating the dialog title, so the entry was searchable as the same string twice.
- **「执行」 no longer expands on a bare hover.** The hover guard checked `isMenuActivated`, a flag that is set on the first menu click and never reset, so after one click anywhere in the menu bar, merely passing the pointer over 「执行」 opened it — sometimes a click was needed and sometimes not. The guard is now `activeMenu` (a menu really is open), which matches how the other four items behave.
- **Plugin rows stopped claiming to be required.** The catalogue is app-owned, so a 「必需」 badge on every row said nothing a reader could act on; `entry.required` is still returned by the backend but is no longer printed. The cancel button also lost its ✕ so it reads like the other actions in the row.
