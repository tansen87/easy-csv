  • 4数字贴右、用等宽。数值列右对齐 + tabular-nums + mono，小数位才对齐；原始字符串一个字符不改，格式只影响排版。

正文颜色从 --muted-foreground(0.556) 提到 88% 墨色。现在这张表里最淡的东西是数据本身——表头比数据还深，这是反的。表头 11px 灰、正文 13px 墨，层级靠大小与深浅，不靠加粗。

5

规则与代价

项取值
卡片宽度560 固定（与节点 width 常量对齐，当前代码里 520 / 560 / 426 / 400 四个数不一致，先统一）
卡片高度44 + 32 + 32×行数 + 26（页脚），8 行封顶；无页脚时省 26。usePipelineLayout 的 height 要跟着实测高度走
落点右 48 → 放不下则分支包围盒下方 48 → 与已有结果卡相撞再下移 高 + 24；首次出现时若完全在视口外，做一次 fitView(padding 0.2)
列宽采样前 50 行 + 表头：数值列 = 最长值 + 24，封顶 160；文本列按内容封 240，剩余空间给最后一列文本
对齐数值右对齐 + tabular-nums + mono；文本左对齐。判数值用「可解析为数字且不含货币/千分位符号」，不做格式化
空值12×1px 短线，不写字符；页脚汇总空值处数
复制一个分体按钮：主键复制 CSV，箭头展开 CSV / Markdown；成功原地变“已复制”

代价

  • 缩放会吃掉字号。卡片在画布坐标系里，fitView 到 0.8 时 13px 正文只有 10.4px。要么限制最小缩放（画布其他内容又放不下），要么接受“看结果前先缩回 100%”。
  • 宽表只能滚。8 列以上在 560 里必然横向滚动，行号槽与首列吸左后，可视区只剩三列多。
  • 落点规则永远在猜。右、下、让位三种分支，加上用户手动拖过的位置要保留，判断逻辑比表格本身复杂；而且卡片会跟着画布一起被拖走。
  • 一张卡一条分支，结果之间没法对照。两张结果卡并排时，6 行 × 2 列还算挤得下，10 行就要各自滚。

好处也说清楚：它保住“结果长在分支末端”这件事，不需要新面板、新状态、新快捷键，是三条路里唯一能在一天内落地且不改产品模型的。
