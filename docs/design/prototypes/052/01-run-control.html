052 · 工具栏「运行」

运行 —— 一个菜单项，一块状态盘

运行本来就和 文件 / 编辑 / 查看 / 工具 / 帮助 并排,这次不改它的位置、尺寸和间距,只改它展开的面板。真正让人搞混的是打开规则不统一:有时点一下「运行」才展开,有时鼠标划过就自己展开 —— 因为悬停守卫用的是 isMenuActivated,而它一旦被点过一次就永远是 true。修法是让它回到菜单栏自己的规则:没有菜单展开时悬停只高亮,已有菜单展开时悬停切过来,点击才展开/收起;再把展开的内容按状态分组,让多标签页并发仍然可见,但不再和「运行」这一个入口混在一起。

产品
把 CSV / DuckDB 的清洗与导出编成管道;菜单栏的「运行」是进入执行状态的唯一入口,面板说明每一页现在处于什么状态。
性格
平实、直白、像仪表盘上的一排读数 —— 入口不抢戏,状态说清楚。
世界
工程台与仪表:同排的菜单项用同一套字与间距,状态灯小而准,读数一律等宽。
两个瞬间
① 运行中菜单项下方一条 2px 墨蓝底轨 ② 面板每行左侧一颗状态灯 + 一行等宽分支读数。

#现状改法
1 打开规则不一致(本次主诉)。useUIState.ts:14 的 isMenuActivated 只被置 true、从不复位;而 MainMenu.tsx:343-349 的 hoverExecuteMenu 用 !activeMenu && !isMenuActivated 判断要不要悬停展开 —— 本次启动点过任意菜单之后,鼠标划过「运行」就直接展开,没点过就必须点一下。 与菜单栏同一条规则:点击展开;悬停只在已有菜单展开时切过来。把 hoverExecuteMenu 的守卫从永不复位的 isMenuActivated 换成 activeMenu —— 不删悬停,「运行」因此重新和文件 / 编辑同组。它仍留在菜单组里,位置、尺寸、间距都不动;要改的是展开以后的面板。
2 按钮叫「运行」,点下去只开菜单。MainMenu.tsx:939-956 的 onClick 是 toggleExecuteMenu;真正启动要再点一行 —— 名字与动作之间差一步,而这一步又和悬停规则叠在一起。 保留菜单项,把动作放进第一行。不做独立的 CTA:运行仍是文件/编辑旁边的一个菜单项,点击展开面板;当前标签页固定排在最前,行尾就是「运行 / 停止」。入口与其它菜单项共用同一套尺寸、间距与 hover。
3 同一行点击,三种后果。:218-223:运行中 / 排队中的行点击只 onSelectTab,其余行点击 onRunTab;已完成的又回到「执行」。用户无法预判这一下会发生什么。 点行仍是快捷方式,但动作被写出来。空闲 / 失败的行,点行 = 运行该页;运行中 / 排队 / 待确认 = 切过去。行尾再摆一颗同语义的按钮(运行 / 停止 / 处理),让「点哪儿会发生什么」不用猜。
4 空闲行的「运行」要悬停才出现。:298-302 用 opacity-0 group-hover:opacity-100;菜单打开时三行看起来都是纯标签,不像能点的东西。 行尾动作常显。「运行」用 9% 墨蓝底 + 墨蓝字,22px 高;它同时承担「这一行可以启动」的说明,不再依赖鼠标。
5 180px 里塞四件事。:958-967 的菜单同时做选页、执行、看进度、取消;宽 180、标签名上限 96px,进度与「取消」一挤,名字先被截断。 240px 面板按状态分组。运行中 / 排队中 / 待确认 / 空闲,组名 10px mono;每行只有灯、名字、读数、动作四个位置。
6 「分支 2/3」是内部术语,而且重复三遍。菜单行 :252-255、画布进度 pill、标签栏「执行中」徽标都在说同一件事,但三处口径不同。 只在两处出现:画布 pill 保留「分支 2/3」;面板行用等宽 分支 2/3 作为读数。工具栏按钮不再背数字,只负责「运行 / 停止」。
7 完成 / 失败徽标常驻菜单。:287-297 把「完成」「失败」做成胶囊,但它们描述历史、不可操作,还和标签栏徽标重复;失败的行反而没有任何「重跑」入口。 失败给红灯 + 「运行」。失败行左侧红点、读数写「上次失败」,动作仍是「运行」(即重跑);「完成」从面板移除,只留在标签栏。
8 运行中只靠一条 2px 线表达。:946-953 把文字转灰,再叠一条 .exec-busy(index.css:654-665);在浅色工具栏里几乎看不见,反而像被禁用;点它只会开菜单,停止入口埋在行内。 入口保持中性,状态交给面板。保留 2px 底轨作为「正在跑」的暗示;完整状态(哪一页、分支 x/y、停止)放在展开的面板与画布 pill 里,不要求一条线讲完三件事。
9 别的页在跑,工具栏不吭声。只有画布 pill 旁边一行 otherTabsRunning(HomeView.tsx:595-599);不看画布就不知道后台还有几条在跑。 运行标签后一颗 6px 蓝点。只要当前页之外有运行中 / 排队 / 待确认,点就亮;数量留在面板的组名后面,不挤工具栏,也不把入口撑宽。

交互 / 键盘 / 边界

两种手势,结果一致。点「运行」= 开 / 关面板;点面板行 = 运行该页(运行中 / 排队 / 待确认则切过去并收起面板),行尾按钮把同一动作再摆一次(处理 = 切到该页,补值框仍按现有 FIFO 弹出)。

悬停跟菜单栏走。没有菜单展开时,悬停「运行」只变底色;已有菜单展开时,移过来就直接切到运行面板。「运行」和文件 / 编辑 / 查看 / 工具 / 帮助 共用这一条规则,不再单独开一套。原先的毛病是守卫用了一个永不复位的 isMenuActivated,已按最小补丁改为 activeMenu。

入口与菜单组一致。高度、padding、字号、hover 与文件 / 编辑 / 查看 / 工具 / 帮助完全相同,中间不留额外间距、不加分隔线、不做实心底色 —— 它只是这一排里的第六个入口。

键盘。Ctrl+R 不变;面板内 Tab 走行尾动作,Enter 触发,Esc 关闭;焦点回到「运行」。

排队与上限。队列满时入口不置灰,点击后该 run 进入 queued,面板「排队」组出现新行;底栏写「最多同时 N 个」,数字取 max_concurrent_runs。

空管道。当前页没有步骤时入口置灰(与现状一致),并在旁边说明「切换到一个带步骤的标签页」;切到有步骤的页后恢复。

完成态不进口。「完成」只在标签栏徽标与结果区出现;面板的「空闲」组只列可运行的页和失败页,避免把历史当待办。

红线。不把「运行」做成独立的实心 CTA、不加 ▾ 子按钮、不改它与菜单组的间距;不改 runsByTab / 并发上限 / 取消逻辑;不做「全部停止」(028 定稿);不显示步骤名与百分比;不做 hover:scale / 循环呼吸灯。

实现落点。入口保持 MainMenu.tsx:932-956 的按钮与样式(只删悬停展开);renderExecRow 重写为「分组 + 行(点行运行 / 切页)+ 行尾动作」;新增 otherRunning 点判定(Object.entries(runs).some(...))。面板用 createPortal 挂到 body —— 否则标题栏的 data-tauri-drag-region 会覆盖面板空白与底栏,拖着会移窗口、双击会最大化。

测试影响。ExecuteMenu.test.tsx 的既有断言(悬停展开、行点击即执行、hover 才出现的运行文案)需要按新语义重写;标签页徽标与 LogPanel 的用例不受影响。
