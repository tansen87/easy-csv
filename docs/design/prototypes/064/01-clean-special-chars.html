PROTOTYPE 064 · CLEAN CHARACTERS

清除符号

拆分坏行经常要勾「忽略引号」，拆出来的好行里仍残留成对的 "、\t、\r 和空行，xan 读取时继续报错。这个动作不解析 CSV，按物理行扫一遍，把会干扰解析的字符去掉或换成空格，另存为干净副本。

为什么紧挨着拆分坏行

拆分坏行负责「把列数不对的行挑走」，清除符号负责「把挑剩下的好行里的脏字符扫掉」。顺序固定，所以位置上连在一起，不跨过分隔线。

原始 CSV→ 拆分坏行→ 清除符号→ xan 可读
  • 菜单文案用「清除符号」，与「拆分坏行」同为动词开头的四字，长度完全一致。
  • 只做一次性文件动作，不进管道、不改原文件。
  • 与其它工具一致：从当前标签页进入时自动带出输入文件。

05 · 实现约定新增一个工具对话框与一个后端命令src-tauri · CleanSpecialCharsDialog
项约定
入口工具菜单「拆分坏行」下方；命令面板 action id clean-special-chars；从当前标签页带出输入文件。
处理单位按物理行扫描，不做 CSV 解析；引号不成对不报错。按字节保留原有非清理内容与行序。
字符处理\r 删除；连续空行合并为一行；\t 与自定义符号固定替换为空格；" 删除；竖线 | 与反斜杠 \ 不处理，原样保留。
换行行尾 \n 始终保留，输出统一 LF。勾选「合并引号内换行」时，成对引号内的物理换行合并为一个空格；引号未闭合则该段按行原样保留，并计入未闭合行数。
输出默认 {stem}_clean{ext}，与输入同目录；可另存为其它路径；禁止与输入同路径。
编码按 UTF-8 读取；非法 UTF-8 直接报错并提示先用「转换编码」。不自动猜编码。
项约定
返回{ output_path, rows, removed_chars, replaced_chars, unclosed_lines, elapsed_ms }，前端据此渲染结果卡；unclosed_lines > 0 时结果卡下方追加一行提示。
大文件逐行流式读写，常量内存；不在前端整文件读入。
记录写入与拆分坏行相同的本地历史（输入、选项、输出、耗时、完成时间），下次打开自动带出。
文案新增 cleanChars* 系列 i18n 键，中英文同步；不写“运行中”文字，运行状态由按钮承担。
测试后端：CRLF、空行、引号、制表符、竖线与反斜杠保留、自定义符号、UTF-8 失败、同路径拒绝；前端：默认勾选、空选禁用、结果卡、历史恢复。

非目标：不修列数、不重新加引号、不改编码、不去 BOM。字段内换行只做「成对引号内合并」这一种确定性处理；引号语义的完整解析不在本工具范围，避免一个对话框承担互相矛盾的规则。
