选中几步之后，复制和删除应该待在哪儿

结论

A + 只在 ≥ 2 步时出现。单张卡的操作留在卡片自己的 hover 条与 ⋯ 菜单里；批量选中时底部托盘出现，计数写单位，删除默认灰、hover 才红，复制/删除后面挂 ⌘C / Del 键帽。位置稳定、不盖节点、不与标签栏抢位置，日志抽屉打开时按现有变量一起上移。底部中心只属于任务托盘；手势提示退到右下角并压成一行小字，有选中时让位——两者永不同时出现。

05落地规则（采纳 A 时）尺寸、状态、文案

尺寸托盘与刻度

  • 高 28，圆角 6，1px hairline，无阴影；左右内边距 2。
  • 计数：等宽 11 + 单位 10（2 步 / 2 steps），后面 1px 分隔线 14 高。
  • 动作：22 高、11 字，不带图标；键帽 9 等宽 + 1px 边框。
  • 位置：底部居中、距底 8——与右下角手势提示同一条底边；日志抽屉打开时再加抽屉高度。

行为出现与消失

  • 只有 selectedNodeIds ≥ 2 才出现；单张选中走卡片 hover 条，不重复。锁定画布时不出现。
  • 删除默认 灰字灰图标，hover 才 danger；不弹二次确认（与今天的 Delete 键一致）。
  • 键盘不变：Ctrl/Cmd C 复制、Delete 删除；托盘只是把键帽写出来。
  • 除按钮外 pointer-events: none；剪切 / 连线 / 框选进行中自动隐藏，避免和手势抢位置。
  • 手势提示：搬到右下角、去掉卡片（只剩 keycap + 文字），有选中托盘时让位隐藏，清空选择后回来。
  • 进入动效只有 120ms 的 opacity + 4px 上浮（复用 quick-enter）；选区数量变化不重播。

不改的部分。复制/删除的实际逻辑、撤销、剪贴板、快捷键、锁定画布的禁用规则一律不动，只换容器、位置与视觉层级；语言文案沿用现有 copy / deleteSteps。
