方案 C：管道作业台

把「运行」从标签页的附属状态提升为一等对象：每条分支是一份作业，一个面板管理所有正在跑、排队和刚完成的管道，跨标签页。

先给结论：C 单独做会多出第四层概念（标签页 → 运行 → 分支 → 作业），执行菜单与作业台的口径还会打架。建议只吸收它的「跨标签页清单」，不引入 job 对象。

02

问题：第四层对象

现在应用里已经有三层。C 加进来的「作业」不是任何现有层级的别名，用户需要重新理解一次。

L1

标签页

一份管道文档：输入、步骤、连线、输出路径。用户可以开很多个。

›
L2

运行

点一次执行产生一个 session，带 runId、队列、取消。一个标签页同时只有一个。

›
L3

分支

一次运行内部的路径单元，今天只出现在进度读数与结果页签里。

›
L4

作业

把 L2 × L3 展开成可单独操作的对象。与执行菜单按标签页列运行的口径不一致。

三个具体冲突

入口重复：标题栏「执行」已经是按标签页的运行列表，作业台再按分支列一次，同一个任务在两处出现。
取消语义：执行菜单取消的是标签页 run，作业台取消的是单个作业；用户不清楚后者会不会影响同标签页的其他分支。
没有新能力：如果不做 A 的节点状态与 B 的去重，作业台只是把「分支」改名成「作业」，既没少算一次，也没让结果更好找。

03

只吸收它的三件事

作业台里真正有价值的是「跨标签页可见」和「单任务操作」。这两点放进方案 A 的运行清单即可，不需要新对象。

吸收 01

跨标签页汇总

运行清单顶部已有「另有 N 个标签页在运行」的弱提示，升级为可展开的一段：按标签页列出运行中的分支与耗时。不引入新页签。

吸收 02

行内单任务操作

方案 A 的每一行已经给了取消、结果、重跑。只看该分支日志 作为行内第三个动作，复用日志面板的 runId 过滤。

吸收 03

输出与结果入口

行尾给出输出路径与「打开输出」，失败行给出错误摘要。与 084 的结果抽屉共用同一份数据，不加第二套。

建议
P0 做方案 A；P1 做 B1（段划分 + 共享段只跑一次）；P2 再做段级并行与输出占位符。C 不进入路线图，只把「跨标签页清单」并进 A 的运行面板。

如果只允许做一件事，选 A：它不改任何执行语义，却能让用户第一次看清「这次到底跑了什么」。如果只允许做一件有技术含量的事，选 B1：它把重复计算拿掉，且结果与今天最接近。

拍板前需要回答的三个问题

1. 段级并发与标签页并发是否共享配额？ 现在是 max_concurrent_runs = 4；段级再乘 4 会瞬间拉起 16 个 xan 进程。建议共享一个池，或段级默认 2。
2. 多入边默认行为？ 按边序拼接会改变现有菱形图的结果语义；拒绝执行会让今天能跑的图不能跑。建议第一版拼接 + 徽标，并在计划页写清。
3. 「运行」页签出现时机？ 常量出现会占掉日志/结果的横向空间；建议只在有运行或有多分支计划时出现，单链管道保持今天的样子。
