方案 B：分段 DAG

节点只执行一次。扇出与扇入之间切成段，段内仍是一条 xan 链，段与段之间物化到临时文件，互不依赖的段并行。

核心取舍：不按单节点拆进程。xan 每步一个进程的启动与 IO 开销会吃掉并行收益，所以执行单位是「段」，不是「节点」。

01

怎么切段

段的边界只有两种：扇出（一个节点有多条出边）与扇入（一个节点有多条入边）。其余连续的单入单出节点留在同一段里，保持一次链式调用。

S1

源到第一个扇出点

从输入或入度 0 的节点开始，穿过单入单出节点，直到遇到分叉。整段一次执行。

S2 / S3

扇出后的每个分支

各自成段，互不依赖，可并行。段内多步仍是一条链，不拆成多次进程调用。

S4

扇入点到下一个扇出点

多入边节点开启新段。默认按边序拼接输入，并在节点上标「合并 N 路」。

例外

特殊节点独占一段

batch-* 与 chart 由前端执行，必须独占段，暂不参与并行。

例子

拓扑
input› S1 filter ┬ S2 groupby S3 sort › head ┴ S4 cat › dedup
调度
S1 S2 ∥ S3 S4 去重 6 步 · 4 段 · 并行 2

同一张图，今天按路径是 2 条分支、A 与 D 各两次；分段后是 4 段、每个节点一次。

03

两个必须拍板的语义

分段本身不改数据含义；真正会改变结果的是多入边和同名输出。这两件事必须在实施前定下来。

语义 01

多入边：默认按边序拼接

今天菱形图的 D 会被执行两次，每次只吃一条前驱。分段后 D 只执行一次，必须决定两条输入怎么合并。第一版建议等价 cat rows，并在节点上明确标出「合并 2 路」，日志写清顺序。

05 cat rows 合并 2 路
输入顺序：S2.csv → S3.csv
等价 xan cat rows S2.csv S3.csv
语义 02

同名输出：要求显式命名

多个终端段写同一路径时，计划页不只警告，而是提供占位符。路径里写 {segment}，落盘时替换成段号；不写就要求改路径才能开始。

out_{segment}.csv
S2 out_S2.csv S3 out_S3.csv S4 out_S4.csv
04

改动面与风险

B 不能一次性全上。建议先做「共享段只跑一次」，稳定后再开并行；多入边语义再往后放一版。

项内容风险
段划分新增纯函数 buildSegments(steps, edges)：拓扑排序、扇出/扇入边界、环检测、孤立节点、batch/chart 强制独占段。中；边界用例多，需覆盖 6 类图
后端物化execute_xan_pipeline 增 outputFile（或 materialize）；复用 pipeline_seq 的临时文件交接；临时目录 RAII 清理。中；大文件多段物化会增加总 IO
调度Kahn 拓扑 + 受限并发；失败段的全部下游标 skipped；取消时杀掉在跑段并清队列。中；并发日志交错
多入边第一版按边序拼接 + 「合并 N 路」徽标；{{input:N}} 留给下一版。高；会改变现有菱形图的结果
输出{segment} 占位符；冲突时计划页阻止开始。低
回归红线单链管道逐项一致；旧 .xanflow 可执行；duckdb 混合链沿用 024 的交接规则。必须

建议的上线顺序

B1 段划分 + 顺序调度（不改并行、不改多入边，只消除重复前缀）→ B2 段级并行 + 失败策略 → B3 {segment} 输出 → B4 多入边 {{input:N}}。B1 就能拿掉最大的浪费，且结果与今天最接近。
