方案 A：分支选择放进「执行」菜单

同一个面板做两级：第一级是标签页运行列表，第二级是该标签页的分支选择。多分支空闲行点击进入选择，单分支保持一键运行；底栏「运行」只做进度与结果。

为什么可行：选择分支属于「启动一次运行」，而「执行」菜单已经承担这个动作。drill-in 只复用一个面板，不需要二级 flyout 的贴边翻转与嵌套键盘；宽度从 240 调到 320 就能放下勾选、链名和覆盖提示。

05

规格与接缝

面板宽度从 240 调到 320；选择级只复用一套组件，不新增二级浮层。选择状态只活在菜单里，关闭即丢弃。

选择级超过 5 行时只滚动分支区；返回、全选、风险和主按钮固定。行悬停时步数换成「只运行」，不新增一列。

  • 第一级：MainMenu 增 pickerTabId；空闲多分支行点击或「分支 ›」进入；单分支保持直接运行。
  • 第二级：selectedIndexes 本地 state，默认全选；‹ 返回 与 Esc 回第一级；再 Esc 关闭菜单。
  • 分支数据：App 计算 branchesByTab: Record<tabId, BranchSummary[]>，摘要只含 index / stepNames / stepCount；输出冲突由 host 计算。
  • 启动：onRunTabBranches(tabId, indexes) → executeForTab(tab, { selectedBranchIndexes })；菜单关闭后走现有校验与变量补值。
  • 宽度：RUN_PANEL_WIDTH 240 → 320；不做宽度动画，避免打开时横向抖动。
  • 底栏：只保留运行面板；不再渲染 680 宽计划页。完整计划页（原型 02）是内容规格，不是第二入口。
