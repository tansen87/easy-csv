1执行完成 → 顶部 Toast（§4.3）：应用现有的 Toast 系统本来就在顶部居中（`components/setting/Toast.tsx`：容器 `fixed top-0 … items-center`，单条 `fixed top-12 left-1/2 -translate-x-1/2`），所以完成提示直接用 `showToast` 即可，位置天然一致，不需要新组件、也不需要另选位置。
文案：管道执行完成 · 3 个步骤 · 0.8s（多分支时写「3 条分支全部完成 · 0.8s」）。不显示行数变化 —— 每个步骤的行数日志面板里已经有了（见右侧面板），Toast 里再重复一遍只是噪音。
唯一需要动的地方：现有 `ToastProps` 只有 message + type，要加一个可选动作 action?: { label, onClick } —— 完成提示带一个「查看结果」（打开日志面板并滚到最后一个步骤）。不带「打开数据概况」：那是可选深入动作，不是「执行完成」的默认下一步，需要的人自己从「更多面板」开。
2日志面板自动打开 —— 已经实现，本方案不动：`hooks/execution/runPipeline.ts:102` 在执行开始时就调用 `setShowLogPanel(true)`（配套 `setShowProgressBar(true)`，结束后 5 秒隐藏进度条）。所以结果本身一直在视野里，这一条从待办里删掉。面板底部那行字只是标注这个事实。
现状步骤失败标记已经存在，本方案不新增任何节点标记：`PipelineStepNode.tsx:265-280` 里 `step.error` 会让节点变成 `border-red-500/70 ring-2 ring-red-500/30`，并在节点内显示红色错误文本（`addLog("error", …)` 在 `runPipeline.ts:254` 也已经写了日志）。不做「每步成功标记」（本次修订）—— 一条管道本来就可能有很多节点，满屏绿点会让工作流看起来更复杂；成功是默认预期，不需要额外装饰。上图的两个步骤节点因此没有任何角标。
已删「结果节点 = 视觉终点」整条删除（本次修订）：不做结果节点的绿色描边 / 外发光，不做节点内嵌的摘要条与「查看结果 / 数据概况」按钮，也不做 fitView 定位到结果节点。结果统一通过「自动打开的日志面板 + 顶部 Toast」呈现，画布上不额外装饰任何节点。上图里的结果节点就是普通节点样式，只有标题与内容不同。
