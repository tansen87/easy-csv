081 · 命令对话框 / 放置位置

改参数时，表单应该待在哪儿

现在点步骤卡片或添加一个操作，都会在窗口正中弹出一块 672×80vh、带遮罩、可拖动的模态表单。它挡住画布、挡住正在改的那一步，又没有固定位置——每次打开都停在中间。下面给四个放置方案，都在同一张画布上对比：右栏检查器、锚定浮层、底部抽屉、宽分栏对话框。推荐右栏检查器（大表单就地展开为宽分栏），理由与尺寸写在最后。

05四个方案怎么选对比
方案 遮挡画布 与步骤的距离 长表单 与现有表面冲突 实现成本 结论
00 现状 · 居中模态 整片 20% 遮罩 无关系 80vh 滚动 无 — 遮罩让人以为在「确认危险操作」，而它只是改参数
A 右栏检查器 让出 470 列 选中即显示 470 内滚动 复用 ViewDock 同列 中 采用 画布完整、无遮罩、无拖动；与「选步骤 → 改参数」一致
B 锚定浮层 局部 最近（12px） 放不下 无 中 适合 2–4 个短参数；长表单必须再跳一次，入口不统一
C 底部抽屉 下半屏 中 最宽（三列） 与日志抽屉同底部 中 宽度最优，但两个底部表面叠层；编辑时看不到右下结果
D 宽分栏对话框 整片遮罩 无关系 最好 无 中 复杂命令的最佳容器；不适合每次微调
建议

A 作为唯一的日常入口，D 作为 A 的展开形态。选中步骤或新加操作 → 右栏显示参数（470 宽，无遮罩）；遇到 batch-*、join、duckdb、chart 这类需要在「参数 / 说明 / 输入列」之间来回看的命令，右栏顶部出现「展开」，点击后同一个表单进入 D 的 800 宽分栏，关闭时回到右栏。B 与 C 不采用：前者装不下长表单，后者与日志抽屉抢同一块地方。

06落地规则（采纳 A + D 时）交互与尺寸

尺寸列宽与门槛

  • 右栏默认 470，可在 420–560 之间拖；小于 420 时表单改为单列。
  • D 展开为 800 × 600，左 532 / 右 268；窗口低于 960 宽时不开第二栏，直接堆叠。
  • 画布最小保留 440；不足时右栏改为覆盖式（仍无遮罩），按 Esc 关闭。

行为打开、保存、关闭

  • 点步骤卡片 → 右栏切到「参数」，标题为 命令 · 步骤名；点空白 → 保持草稿并回到上一个面板。
  • 新加操作 → 同一位置，标题为 新建 · 命令，底部按钮为「添加步骤」。
  • 无遮罩，点画布不会关闭表单，避免误触丢改动；关闭只有 ×、Esc、取消、保存四个动作。
  • 切换步骤时先提交当前草稿（与今天点「更新步骤」一致），不弹二次确认。
  • Cmd/Ctrl + Enter 保存，Esc 取消；焦点进入第一个参数，Tab 在参数间移动。

不改的部分。命令表单本身（字段、校验、参数序列化、帮助文档）一律不动，只换容器；「文档」按钮继续复用现有帮助；批量类表单的状态与运行逻辑不迁移。现有 CommandDialog 的拖动、遮罩与居中逻辑删除，`offset` 状态一并移除。

为什么不是 B/C。表单长度不是均匀的：`search` 有 20 多个字段、`duckdb` 至少要 240px 编辑器、`batch-*` 要列目录。B 的 388 宽只能覆盖最简单的一类，剩下的还是要跳走；C 的宽度最好，但底部已经被日志抽屉占用，两个抽屉叠在一起时「编辑」和「看日志」会互相顶掉。
