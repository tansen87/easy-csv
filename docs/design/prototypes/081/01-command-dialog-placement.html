02.1拖动掉帧：上一版 B 为什么卡，这次怎么修React Flow store → 纯数学 → 只写 transform

旧每帧读布局，还把位置塞进 React

  • rAF 轮询：不管卡片动没动，每一帧都跑一次定位。
  • getBoundingClientRect：每帧读卡片矩形，读一次就逼浏览器重算布局。
  • 位置进 state：每帧重渲染整个参数表单（search 有二十多个字段）。
  • 结果：拖卡片时浮层慢半拍，长表单掉帧最明显。

新事件驱动，只写一条 transform

  • 位置 = 卡片流坐标 × 视口 zoom + 视口平移，全是数字运算，不读 DOM。
  • 订阅 React Flow store 的节点与 transform：卡片真的动才触发。
  • 只给浮层写 translate3d；表单子树不参与重渲染，交给合成器。
  • 画布尺寸由 ResizeObserver 缓存，拖动 / 平移 / 缩放期间零布局读取。
结果

拖卡片、按住空格平移、滚轮缩放，浮层都贴着卡片走，帧率与不开浮层时一致。标题栏仍可拖：拖的是「卡片 + 浮层」这一体，拖动量写进步骤节点（松手保存），浮层锚在节点上自然跟随；只有新加命令、没有卡片时才单独移动浮层。

方案 遮挡画布 与步骤的距离 长表单 与现有表面冲突 实现成本 结论

A 右栏检查器 让出 470 列 选中即显示 470 内滚动 复用 ViewDock 同列 中 不采用 画布要让出 470 列，工具被推到视线另一侧

C 底部抽屉 下半屏 中 最宽（三列） 与日志抽屉同底部 中 宽度最优，但两个底部表面叠层；编辑时看不到右下结果

结论

B 作为唯一入口。点步骤卡或新加操作 → 浮层贴在卡片右侧 12px（无卡片时落在画布中心），同一个表单覆盖全部命令：短表单自然高度，长表单字段区滚动、页脚不动。A 让画布让出一整列，C 与日志抽屉抢底部，D 的遮罩在轻操作里太重，都不采用。上一版 B 的拖动掉帧用「store 订阅 + 纯数学 + 只写 transform」解决（§02.1），与不开浮层时同帧率。

06落地规则（采纳 B 时）交互与尺寸

尺寸浮层与边距

  • 宽 480；窄画布时取 画布宽 − 16（最小 280），不横向溢出。
  • 最高 560，同样不超过画布高 − 16；字段区滚动，页脚固定。
  • 贴卡间距 12；四周保留 8。右侧放不下翻到左侧，仍放不下就夹在画布内。
  • 间距以卡片外框为准（布局给节点的名义宽度与卡片实际宽度不同），左右两侧因此相等。
  • 头 40（步骤名 · 命令名 · 文档 · 关闭），表单页脚沿用现有 52–56。

行为打开、跟随、关闭

  • 点步骤卡片 → 浮层出现在该卡右侧，标题为 命令 · 步骤名；再点另一张卡直接换过去。
  • 拖卡片 / 平移 / 缩放画布 → 浮层跟着走，位置由 React Flow 坐标算出，不轮询。
  • 新加操作没有卡片 → 浮层落在画布中心，标题为 新建 · 命令，底部按钮为「添加步骤」。
  • 无遮罩；拖标题栏 = 卡片与浮层一起移动（步骤位置随拖动更新、松手保存，未移动的点击不写位置）；没有卡片时浮层单独移动。点画布不关闭（防误触丢草稿），Esc / × / 取消 / 提交才关。
  • 焦点进入第一个参数；切换步骤沿用「先提交当前草稿」的现有语义。

不改的部分。命令表单本身（字段、校验、参数序列化、帮助文档）一律不动，只换容器；「文档」按钮继续复用现有帮助；批量类表单的状态与运行逻辑不迁移。旧容器（居中模态、右栏检查器、宽分栏）的拖动、遮罩、展开/收起状态全部删除。

为什么只留一个容器。表单长度不均匀：`search` 二十多个字段、`duckdb` 要 240px 编辑器、`batch-*` 要列目录。B 用「自然高度 + 内部滚动 + 最高 560」覆盖全部形态，不再需要「长表单跳去另一个地方」，入口只有一处；A 让画布让位，C 与日志抽屉抢底部，D 的遮罩对轻操作太重，因此都不保留。
