  2. 搜索框在右栏顶部、吸顶 —— 它过滤的是列表,就该挨着列表;左栏只有 184px,放不下输入框 + 结果数 + 清除。

  4. 整行可点 = 委托给该行控件(开关行点任意处即切换、下拉行点任意处即展开),与 macOS「系统设置」一致;危险行例外 —— 四个「清除…」行只有按钮本身可点,点描述就删数据是不可接受的。
  5. 三处呈现订正 —— ① 「清除执行历史」从 AI 组移到「帮助与数据」(SettingsTabContent.tsx:715-723);② 「自定义服务商设置」改常显行,不满足条件时禁用 + 说明,不再凭空出现/消失;③ AI 的四按钮簇拆成 4 个独立行(于是每一行都能被搜到)。
  6. 当前分组高亮 —— 取「视口顶部之上最近的分组标题」,基于 offsetTop 比较而非 IntersectionObserver(后者在短分组快速滚动时会在两组间抖动)。

  8. 不给行加图标 —— 18 行各配一个图标会把「一眼扫完一列」变成「看图标猜含义」,行高也会被迫加高。高度与注意力全留给标题 / 描述 / 控件三列。

浏览态下这一段是「更新 / 帮助与数据 / AI」的完整列表;搜索后只剩 4 行 —— 零命中的分组被隐藏,命中的分组标题保留下来当作上下文。
左栏把不匹配的分组降灰(不隐藏、不重排,保住方位感),点灰分组会先清空搜索再跳过去。
搜索期间滚动联动关闭 —— 此时「当前分组」没有意义,继续高亮会误导。
  1. 匹配标题 + 描述 + 别名 —— 例如输入 dark 能命中的是「主题」(keywords 里带了 dark / theme / 暗色 / 配色)。别名表是人工数据,不进 i18n。
  2. 分词按 AND —— 托盘 通知 只留同时命中的行;大小写不敏感;中文按子串匹配(不做分词)。
  3. 命中高亮 —— 用 <mark>,标题与描述都高亮(读屏可识别)。
  4. 不打散、不按相关度重排 —— 结果保持与浏览态一致的顺序。设置项不该"跳来跳去"。
  5. 界面上不出现任何计数 —— 分组条数与搜索结果数都不显示(列表本身就是计数);结果数只走一个 sr-only 的 aria-live 播报,给读屏用。清空是输入框内的 ✕ 图标,刻意不用「清除」两个字 —— 这一屏已经有 4 个「清除(数据)」按钮了,同一个词不能有两种含义。
  6. 键盘 —— 焦点不在输入框时按 / 聚焦;Esc 清空;焦点在搜索框时 ↑/↓ 移到结果行、Enter 触发。
  7. 空状态 —— 没有匹配「xxx」的设置 + 一行建议:试试「托盘」「暗色」「并发」。

A搜索

解决的问题是「知道名字、不想滚」。它不取代目录:目录回答「我还能去哪」,搜索回答「我要的那一项在哪」。

不做模糊 / 拼音匹配 —— 18 项规模下别名表的收益远高于模糊匹配的实现与调参成本;条目翻倍后再议。

B每设置一行

三列网格:标题 150px、描述 minmax(0,1fr)、控件右对齐。窗口变窄时先截描述,标题不换行。

行高从约 76px 降到 34~36px(约 2 倍密度)。先有行密度,搜索才有意义 —— 列表还那么长的话,搜索只能是补丁。

C目录

8 条分组,点击跳到该组并把焦点移给组标题(tabIndex={-1}),键盘用户跳过去的 Tab 落点就在这一组的行里。

契约:行 id 唯一;分组在左栏与右栏各出现一次、由同一份数据渲染。两条都有契约测试双向比对。

需要拍板(详见设计文档 §8)

  • 侧栏是否保留:保留 = 常驻方位感 + 同组内跳转;去掉 = 每行描述可用宽度从约 380px 增到约 540px,形态变成 VS Code 的「搜索 + 一条列表」。
  • 分组粒度:本稿 7 组 / 18 行。备选 6 组(把「更新」并入「帮助与数据」)或 8 组(拆开 AI)。
  • / 作为搜索快捷键是否可接受(现有快捷键有 Ctrl+K / Alt+C / Ctrl+R 等;/ 只在焦点不在输入框时生效)。
  • 「恢复默认 / 保存设置」的语义不一致(语言、主题、分隔符按下即落库,其余 6 项要按保存):建议不在本次统一,单开一稿。
本原型只表达结构:分组、搜索、行布局与联动。设置项的取值域、默认值、落库时机与文案均与 0.7.0 一致, 相对现状只有三处呈现变更(「清除执行历史」归类、「自定义服务商设置」常显、AI 四按钮拆行)。 色值取自 src/index.css 的浅色令牌;插件管理是唯一不是一行的条目(整块嵌入 PluginManager)。
