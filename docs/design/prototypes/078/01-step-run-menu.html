078 · 管道画布 / 步骤右键菜单

从此步运行、导出此步结果：把上游导出的 CSV 当成这一次的输入

场景：「按地区汇总」报错，但之前已经从「去重」导出过结果。过去只能改标签页的输入文件、再把整条管道重跑一遍；现在从这一步「从此步运行」，输入默认就是上游上次导出的那份 CSV，只跑这一步及之后。步骤卡片不带序号，范围用步骤名表达。菜单入口也不再依赖右键模式：卡片上的 ⋯ 直接打开同一份菜单，右键继续只负责连接与切割。

为什么不做「右键点击 = 菜单、右键拖动 = 切割」。靠位移阈值区分点击与拖动，会出现“手抖一下切断了卡片”的误操作；而且 027 已定红线：连线手势一律不改，右键在步骤上起手就是连线。把菜单挪到卡片自己的 ⋯ 上，既不碰手势，也不用再切模式。

07两项如何衔接导出 → 运行 是同一条链的两端
A

为什么「从此步运行」这次成立。它不假装上游已经算过，而是明确换一份输入：上游最近一次导出的 CSV。所以第 3 步报错、第 2 步导出过时，右击第 3 步即可只跑「按地区汇总」及其下游，标签页的输入文件保持不动。没有导出过时，第一次运行会先让你选文件，之后记住。

B

两项的范围不同，文案必须说清。「从此步运行」= 从此步到分支终点，输入是外部 CSV；「导出此步结果」= 从标签页输入到这一步，结果写盘。前者依赖后者留下的文件，这是它们唯一但关键的耦合。

删除危险红字、不填色；单独分隔，不与运行相邻

落地提醒

  • 范围：新增纯函数 `buildSuffixFromStep()`（沿边取此步到分支终点），与现有 `buildPrefixToStep()` 对称。
  • 输入覆盖：执行时把 `inputFile` 换成来源文件，其余命令序列化沿用 `serializeStepParams`；标签页的输入指针不改。
  • 记住来源：按「标签页 + 步骤」记住该步上次导出的绝对路径（与 020/025 的“上次记录”同一套 localStorage 思路）；文件被删则退回选择文件。
  • 导出不变：仍走 `useSaveIntermediate()` 的前缀执行，只是文案与菜单分组调整。
  • 位置：实际菜单出现在光标处；原型把它画在卡片右侧，只为同时看清卡片与菜单。
