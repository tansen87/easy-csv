原型 073-01 · 2026-11-22

菜单栏命令输入框 —— 把「命令面板」和「搜索」收进同一个开口

菜单栏中部加一个常驻输入框（› 搜索命令、步骤或文件），点击/聚焦即在它下方展开面板：空查询是编号目录，一打字就跨来源检索（操作 / 命令 / 步骤 / 文件 / 标签页 / 模板）。原 Ctrl K 的居中模态与画布 Ctrl F 浮层都并进这里；查看 菜单里的两项随之删除。

现状审计8 条 · 代码位置可核对
  1. 唯一入口藏在 查看 二级菜单第一项（MainMenu.tsx:719-734），画布上没有任何可见的命令入口；只有记住 Ctrl K 才找得到。
  2. 打开后是 560px 的居中模态（CommandPalette.tsx:285-296）：pt-12 + 30% 遮罩，整块画布被压暗，选完又消失——每次都是一次「离开画布 / 回到画布」。
  3. 面板自己还带一条 52px 输入行，与菜单栏隔着遮罩；视线和手要一起从顶部移到屏幕中上，而菜单栏中部那条约 500px 的空白（MainMenu.tsx:1187-1191 的拖拽带）什么也不做。
  4. 97 项混在一个列表里：空查询按「常用操作 → 命令 → 标签页 → 文件 → 模板」平铺，第一屏永远是操作，不是「我刚才想做的那件事」。
  5. 画布搜索（Ctrl F）是另一个浮层（SearchOverlay.tsx），只搜步骤名；命令与步骤各搜各的，同一个词要试两个地方。
  6. 同一件事目前有三个入口：Ctrl K（操作/命令/文件/标签页/模板）、Ctrl F（步骤）、命令停靠面板（072，61 个操作）。
  7. 菜单栏右端 ⌘ 按钮打开的是另一个命令面板（072 的 260px 目录），与 Ctrl K 是同一份 61 条数据的两种呈现。
  8. 同一条 filter 在两处行语法不同：072 目录 40px 两行（命令名 + 中文描述），Ctrl K 34px 单行（名称 + 描述在右），同一个东西长得不一样。

形态对比：为什么不是居中模态

选项判断理由
A 菜单栏输入框 + 下方面板（采纳）采纳点在哪、打在哪；面板不盖画布中心；输入框常驻 = 入口本身可被发现；窗口变窄时宽度自己收。
B 居中模态（现状 053）弃用遮罩压暗整块画布，选完消失；输入行与菜单栏分离，手要在屏幕中上重新找位置。
C 只在面板里检索、菜单栏放静态提示弃用点击后还得再点一次输入框；两次定位。
D 输入框放右端、靠近图标组弃用与 AI / 数据预览停靠带争抢；且右侧已有 4 枚图标，再加会挤成工具条。
