命令面板 —— 一条命令行，一份可读的排序

Ctrl+K 是这个产品里最快的路径:97 条入口(26 个操作、61 条 xan 命令、标签页、最近文件、模板)全靠键盘取用。现在它能用但不好用——一打开就是 97 行同权重的列表,搜索只做 includes,命中了也不告诉你命中在哪里;26 个操作和 61 条命令被放进同一个平铺的「操作」组;面板 576 宽、420 高,坐在 20vh 的位置上,底下垫一层毛玻璃。这次不改它能做什么,只改它怎么被读:一条等宽的查询行、一份按相关度排过的单列结果、一处只属于「你输入的字」的品牌色。

产品
把 CSV 清洗编成管道;Ctrl+K 是键盘用户的唯一入口,要在一秒内找到 97 个入口里的任意一个。
性格
精确、快、不寒暄 —— 像一个会记住你打到第几个字的终端。
世界
命令行与表格列:等宽的名字、键帽、一个 › 提示符;正文仍是中性灰,只有命中处上墨蓝。
两个瞬间

交互 / 键盘 / 边界

一条输入框做三件事。打中文搜名字,打英文搜命令名(filter),打文件名搜最近文件;都进同一个分数表,不切模式、不加前缀语法。> 之类的作用域前缀不做 —— 一个有 97 项的列表不值得记第二套语法。

键盘。Ctrl+K 开,Esc 关;上下在结果里回环移动,Enter 执行当前行并关闭,Tab 不具备「补全」语义(不做行内补全)。输入法组字期间Enter不触发执行(e.isComposing),这一条现在就是缺的。

鼠标。悬停只改高亮,不改列表;进入行时复位键盘模式,箭头键立刻重新接管。点击行 = 执行并关闭,与 Enter 完全同义。

空查询是一条完整的可滚清单。操作 → 标签页 → 最近文件 → 模板 → 命令,五段按固定顺序分区,不折叠、不截断、不加「还有 N 条」的尾巴 —— 分区只是让滚动时有地标。真正的入口是输入:空查询负责「让你知道有什么」,打字负责「一秒到那一条」。

拼音首字母是可选层。用 scripts/gen-pinyin-initials.mjs 从标签字表生成一个静态 Record<char, initial>(约 200 个字),运行时不引任何依赖;查不到的字跳过,只会少匹配,不会多匹配。首字母命中不参与上色。

不做的。不做最近使用排序(需要新的持久化 key 与清理策略)、不做预览面板、不做 > 作用域前缀、不做「只剩一条自动执行」、不做行内补全;命令面板不复用 CommandList 的拖拽浮动面板。

实现落点。面板结构在 src/modules/logs/CommandPalette.tsx;排序抽到同目录 lib/scoreItem.ts(纯函数,便于单测);来源标签由 group 反查,不改 PaletteItem 的公共字段,只加一个可选 source?: "action" | "tab" | "file" | "template" | "command",由 App.tsx 在构造 items 时填。

测试影响。CommandPalette.test.tsx 的 11 条断言里,「渲染分组」「按 query 过滤」「keywords 与快捷键匹配」保持语义;re-enables hover selection after the mouse moves 要改成 mouseEnter 触发(复位点从 dialog 搬到行);另需新增:分数排序、高亮片段、回环移动、isComposing 不执行。断言里用 container.textContent 找名字的方式仍然可用 —— 高亮只是把命中片段包进 <b>,文本不变。
