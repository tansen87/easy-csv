维度A 参数清单B 双栏检查器C 命令优先
最适合 ≤8 项的命令（多数） ≥8 项的长命令 熟练用户、键盘流、需要复跑命令的场景
一屏信息量 高：所有常用项可见，无需滚动 中：一次只看一组，靠左栏导航 中高：命令全貌 + 单个参数编辑
新手友好 最好：中文名 + 说明 + 控件 好：分组本身在教参数结构 最差：先看懂命令才敢点
与现有代码的改动面 小：抽一个字段组件，62 个表单逐步迁移 中：多一套布局 + 参数量阈值切换 大：参数要能双向映射回 token，撤销/校验都要重写
需要的新数据 参数描述（已有）、表头（已传入但没用） 同 A + 分组元数据（可推导：必填/有默认/其余） 同 A + 参数的序列化顺序（已有 helpers）
风险 字段多时仍需滚动，但滚的是清单不是表单 152px 常驻左栏，短命令会显空 把 CLI 语法暴露给不读命令的人

建议的落地顺序：A 打底，B 供长命令，C 作为 A 的“看命令”开关。三者并不互斥——字段组件（名字 / flag / 说明 / 控件）在 A、B、C 中是同一个；先把它抽出来，62 个表单逐个换成数据驱动，A 立刻生效；参数量 ≥8 时切 B 的两栏；再把 C 的命令行做成 A 底部那条预览的“展开可编辑”形态，谁想直接改命令谁展开。
这样第一步只动一个组件和 8 个左右的高频表单，就能验证「人话名 + flag 溯源 + 表头选择」是否真的减少了填错。
