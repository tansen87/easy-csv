1含逗号的引号字段 → 整表列错位P0 · 会撒谎

今天的行为

源文件一行是 "Smith, John",42。chart 分支不用 Rust 的 csv 解析器, 而是在 JS 里 line.split(","),只剥掉首尾引号:

列 0列 1列 2
"SmithJohn"42
"LeeAnna"37

后果:列整体错位 → 图表拿 John" 当数值列 → parseFloat 得 NaN → 按 §3.3 变成 0 → 整张图全是 0,却不报错。
同一文件的预览表却是对的(预览走 Rust csv crate),用户只会更困惑。

建议

chart 分支改为复用后端读取能力(新增 read_chart_source 或复用 read_tabular_file),不在 JS 里再实现一遍 CSV 解析。

nameage
Smith, John42
Lee, Anna37

收益:预览与图表同源,引号内逗号/换行、转义引号 "" 全部正确; 从根上消掉"两套解析实现"这个持续成本。

5三种不同的「空」,今天是同一张脸P0 · 会撒谎

今天的行为

现状不一致:饼图 / 词云 / 热力图给一句 无数据可显示, 而 line / bar / scatter 什么都不给 —— 只留空坐标轴。

·
情形 A:文件真的没有数据行
饼图/词云显示「无数据可显示」;折线图显示空白轴
·
情形 B:x 列名不存在
饼图/词云显示「无数据可显示」;折线图显示空白轴
·
情形 C:列存在,但该列全是空值
饼图/词云显示「无数据可显示」;折线图显示空白轴

核心问题:三种完全不同、修法也完全不同的情况(换文件 / 改列名 / 查数据质量), 给出了同一句无信息的提示 —— 用户无从知道下一步做什么。

建议

统一为空/错状态组件,按原因分派,每种都给出下一步动作。

∅
没有可绘制的数据
输入文件没有数据行。
→ 检查上一步筛选条件是否过严
▲
找不到列「Region」
列名不匹配,该文件可用列: region sales orders
→ 修改 x 列名后重新执行
!
列「sales」没有可用的数值
共 1,204 行,全部为空或非数值(如 N/A、-)。
→ 用 map 步骤清理该列,或改选其它列

与 §3.4 同源:都由 processChartData 返回结构化原因驱动。 顺带把英文标题漏出也一并解决(今天面板标题会直接显示 heatmap)。
