方案 B · 双列 + 书脊

停靠区变成一排真实的列：最多展开两列，第三列不盖别人，而是收成 44px 书脊——图标加竖排标题，像账本里的页签。宽度不够时按“最久没用”自动收列，画布永远留得住 440。

这是三个方案里唯一做到同时看两列的；代价是多一个概念（书脊），并且要有宽度预算。
1

两列展开，第三列进书脊

列的位置固定：概览 → 版本 → 血缘 → 变量，从左到右，和查看菜单的顺序一致。收成书脊时它留在原位，只把宽度从 320 改成 44，别的列一动不动。

4

规则

项取值
列序固定 概览 → 版本 → 血缘 → 变量。开关不会让列换位置，只让宽度在 0 / 44 / 320 之间变
同时展开最多 2 列；第三个被打开时，把最久没用的那列收成书脊（不是你刚点的那列）
宽度预算画布 ≥ 440：1240 − AI − Σ列 不足就继续收列，全收完仍不足则保持 44 书脊
列宽320 默认，可拖 280–420；四列共用一个宽度
列头36px：序号 + 标题 + 该列动作 + 收起（chevron）+ 关闭（×）。收起 = 进书脊，关闭 = 从停靠区移除
菜单四项仍是复选，但右端写出位置：展开 / 书脊 / 关，勾只表示“在停靠区里”
宽度来源一个 useViewDock() 同时给出 slots[] 与 dockWidth，画布/标签页带/日志不再各算各的

代价

  • 多一个概念。“书脊”要一次解释（悬停提示 + 首次收起时 1.5 秒的行内提示），之后靠竖排标题自解释。
  • 宽度会自己变。开 AI 时某一列悄悄收起来，需要一行 toast 说明“数据概览已收进书脊”，否则像丢了。
  • 实现最大。一个 reducer 管三态与 LRU，四列共享宽度与拖拽，还要把 4 个面板的头部统一。
