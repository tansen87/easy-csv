原型 056 · map 表达式编辑器

把 map 的表达式编辑器做成和 DuckDB 编辑器同一套语言

范围：MapForm 与 ExpressionEditor。字段、参数、提交逻辑都不变——把它对齐 DuckDB 编辑器的工艺：补全贴着光标、类型码代替彩色胶囊、签名与键帽进弹层、函数签名做成编辑器底部状态条；选项保持参数名，只做对齐。红圈是现状问题，蓝圈是改法。

产品
在 672 宽的对话框里写一条 xan 表达式，为 CSV 算出新列。
性格
精确、安静、可被检验。像在手边调试一条表达式，不像在填表。
世界
账本纸面与仪器面板：白纸上的等宽字，一条墨蓝的下划线。
时刻
① 贴着光标的补全卡（类型码 / 前缀高亮 / 签名 / 键帽）；② 底部的函数签名与当前参数下划线。
签名
24px 的等宽类型码列 col / fn / kw / op，与 DuckDB 编辑器共用同一套语言。

问题清单
#位置现状改法
1map.tsx:14字段标签写的是原始参数名 expression，中文界面里也还是英文。标签「表达式」；原始名退到右上角 10.5px 等宽小字。
2ExpressionEditor.tsx:209-261补全固定在编辑器底部、整宽弹出（mt-3 w-full），与光标脱节，还盖住参数提示与选项。沿用 DuckDB 的 caretPosition / placeSuggestions：贴光标、宽 420、上下翻转、3–6 行。
3ExpressionEditor.tsx:228-240四种类型各用一个彩色胶囊（function / keyword / column / operator），一屏四色，靠颜色扫读。统一成等宽类型码列 fn / kw / col / op；只有选中项用墨蓝。
4ExpressionEditor.tsx:219-256行高 36px、没有签名列、没有说明、没有键帽；最多只能扫到 4 行。28px 行、签名右对齐、底部 32px 说明条与键帽；3–6 行完整可见。
5ExpressionEditor.tsx:214列表高度写死成 h-42（168px），36px 行只放得下 4 行，也不会根据可用空间收缩或翻转。按可用空间取 3–6 行（行 28 + 内边距 8），不写死高度。
6ExpressionEditor.tsx:263-290函数签名是一个独立的灰色条，当前参数是实心 brand 药丸 + 700 字重，和主按钮争主次。签名并入编辑器底部状态条，当前参数改成墨蓝下划线；右侧给「第几个参数」。
7map.tsx:29-70三个开关与线程数挤在同一行：线程数没有可见名称，只靠占位符。参数名本身保持英文。四项对齐成一行：勾选框 + 参数名；线程数用 threads 作标签 + 88px 输入框，不加解释。
8ExpressionEditor.tsx:179-206编辑器固定 120px、透明边框；DuckDB 编辑器是 240px、有边框与 2px 焦点环，两个编辑器像两个产品。240px（212 内容 + 28 状态条）、13/22 等宽、1px 边框 + 2px 墨蓝焦点环。
9map.tsx:35-40原生 3.5px 勾选框，与项目其他自绘勾选（13px brand 实心）不一致。沿用 13px 勾选框，与右键快捷面板同一套。
10autocomplete.ts:58-79当前词为空时也弹全量建议（每次空格/左括号都弹），噪声大。至少输入 1 个字符才出建议；空词只留状态条里的提示。
11ExpressionEditor.tsx:218建议行用 type-label 作 key，数据里两个 count 会撞 key 并出现两行。按标签去重（或把不同签名合并成一行）。
12CommandDialog + MapForm表达式为空时「添加」仍可点，点了才知道不行。空表达式禁用主按钮，并在其上方写「还缺 表达式」。
规格
项值
对话框宽 672、头部 52、底部 56、内容内边距 20；与现在一致，不动外壳。
编辑器高 240（212 内容 + 28 状态条）；等宽 13 / 22；内边距 12 / 14；圆角 8；边框 1px，焦点 2px 墨蓝 12%。内容超过 212 后内部滚动，最长到 360。
补全卡宽 420（不超过编辑器宽 − 8）；行 28；内边距 4；行数 3–6；距光标 4；下方放不下时翻到上一行；圆角 8；中性阴影。
补全行三列 24 / 1fr / auto：类型码 mono 10.5、标签 mono 13/500、签名 mono 11.5 右对齐；选中行 = brand-soft + 左侧 2px 竖线。
弹层底部高 32；左「函数 / 列 / 关键字 / 运算符 · 说明」，右 ↑↓ / Tab / Esc 键帽（16px，mono 9.5）。
状态条高 28；mono 11.5；左侧函数签名，当前参数 brand + 2px 下划线；右侧「第几个参数」或 xan；不在函数里时显示「输入列名、函数或运算符」。
选项距编辑器 16；顶部 1px 细线 + 14 内边距；标题 11.5；四列网格，列距 12；参数名 mono 11.5；勾选框 13 / 圆角 3；线程输入 88 × 28；不加解释文案。
图标 / 动效补全卡不做缩放入场；只做 60ms 内透明度变化。选中行只换底色与竖线，不移动。
键盘↑↓ 换行、Tab / Enter 接受、Esc 先关补全再关对话框；鼠标点选不夺焦。
文案对照
位置现状改后理由
字段标签expression表达式 （右上角 expression）中文界面先说人话，原始参数名留给需要查文档的人。
选项overwrite / filter / parallel + 原生勾选保留参数名，四项对齐，统一勾选框参数名是 xan 的接口，不翻译、不加解释。
线程只有占位符threads + 输入框给它一个可见名称，仍然不解释。
补全类型彩色胶囊 function / keywordfn · 底部写「函数」列表里只需要扫读的短码，全称放底部。
无匹配列表直接消失无匹配 “zz” ＋ Esc让「没有结果」也是一个明确状态。
空状态按钮可点还缺 表达式 ＋ 禁用按钮先解释，再禁用。
实施映射
文件改动
components/expression/ExpressionEditor.tsx对齐 DuckDB：光标定位与翻转、类型码 / 签名 / 弹层底部、无匹配、去重；高度 240 + 状态条；只显示 1 个字符以上的建议。
components/expression/DuckdbEditor.tsx建议：把 caretPosition / placeSuggestions / 弹层外壳抽成共享模块，两个编辑器共用一套，不复制 200 行。
modules/dialogs/command/forms/map.tsx字段标签、选项四列（保留参数名）、threads 标签；表达式为空时给 CommandFormShell 传 disabled，并显示缺项说明。
i18n新增 mapExpression、mapOptions、exprHint、exprNoMatch、exprMissing、exprKindFunction / Column / Keyword / Operator。选项标签直接用参数名，不加 key。
不做不搬 DuckDB 的「插入模板」：map 的模板必须是真实列名，属于新功能；需要的话单开一稿，从当前选中列生成。

原型只改工艺与文案：表达式语法、map 的参数、提交与步骤命名都不变。弹层定位与键帽沿用 DuckDB 编辑器已验证的实现方式，避免两套编辑器行为漂移。
