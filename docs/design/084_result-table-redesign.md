## 1. 现状审计

一次执行后，每条成功分支挂一张结果卡在画布最右侧。它承担了「看结果」的全部职责，但既不像报表，也不在视口里。

## 2. 方向(unslop 五条)

- **产品**: 桌面 CSV 管道工具。把 xan 的命令串成一条管道，一边看数据一边改管道。
- **性格**: 精确、克制、有账房的耐心——不是「现代简洁」。
- **世界**: 账本与索引卡。细横线、右对齐的金额、页边的编号。用户盯着数字看一天，界面要像一张好账页。
- **时刻**: 结果表本身。整屏唯一有「厚度」的地方：数字按位对齐、金额贴住右缘、行号像账页的序。其余全是灰线与墨色。
- **签名**: `01 › 02 › 03` 的步骤索引 + 34px 行号槽。结果不是「一张有数据的卡」，是「第 3 步之后的那一页」。

一句话: 结果是一页账，不是一扇窗。

## 3. 三个方案

### 方案 A · 画布内锚定卡 → [原型 01](prototypes/084/01-canvas-anchored-card.html)

- **形态**: 仍是画布节点，560 宽，高度随行数(44 + 32 + 32×行 + 26)。
- **版式**: 标题改编号链；表头一条 22% 实线、行间 8% 细线、无竖线；行号槽 34；数值右对齐 + `tabular-nums` + mono；空值 12×1px 短线；页脚写空值处数。
- **位置**: 右 48 → 放不下则分支包围盒下方 48 → 与已有结果卡相撞再下移 `高 + 24`；首次落在视口外时做一次 `fitView`。
- **代价**: 仍在画布坐标系里(缩放吃字号)；560 宽容不下 8 列；落点规则有三个分支，永远在猜；多张结果无法并排对照。

### 方案 B · 底部结果抽屉 → [原型 02](prototypes/084/02-bottom-result-dock.html) **(推荐)**

- **形态**: 结果离开画布，进入内容区底部的抽屉，与日志**同一张纸的两个页签**(复用 071)。默认 260 高，可拖 160–70%，记忆高度。
- **面板切换**: **一排页签**(`日志 21` / `结果 6`)，当前项浅底 + 加粗；**日志永远排第一**，结果按分支跟在后面(`结果 1`、`结果 2`)。曾试过下拉选择器，视觉上像多了一个输入框、也藏起了「还有几页」，回退为页签(见 §8 差异 6)。
- **版式**: 页签、步骤链、计数与复制**同处一行 32px**；日志页签同理——等级 chips、范围切换、搜索与导出/目录/历史/清空都在这一行，`LogPanel` 通过 `DockHeaderSlotContext` 把工具栏 portal 进抽屉的头行（筛选状态仍留在面板里）。表头 32、行 30；**没有页脚**（空值计数与截断提示已并入页签行，见 §8 差异 7）；抽屉宽 1240，8 列一次看完。
- **窄抽屉的降级**: 抽屉宽 < 700（开了 AI 与查看列）时，范围切换隐藏；等级 chips 横向滚动并在溢出时右侧渐隐，搜索框收到 96px 下限，动作图标不动——宁可滚筛选，也不压字号或换行。
- **步骤名自带编号**（示例管道叫「1 去掉空金额」）时会与链条的 `01` 重复，显示时仅在编号与位置一致时剥掉。
- **画布**: 分支末端挂一枚折角 `结果 · 6 行 × 2 列 | 查看`，虚线连到最后一步；点击打开抽屉并定位到该分支。
- **快捷键**: `Alt+R` 开关结果抽屉(登记进 083)，`Alt+Q` 仍是日志，`Esc` 收起。
- **代价**: 结果的「空间归属」变弱，全靠折角与「定位分支」补；占 304 竖向空间；要动 071 的抽屉壳(抽成共享 `BottomDock`，把 082 的托盘偏移改挂 `--bottom-dock-height`)。**三案里唯一需要改公共容器的。**

### 方案 C · 右侧结果列 → [原型 03](prototypes/084/03-right-result-column.html)

- **形态**: 结果成为停靠区的一列，420 宽(可拖 380–520)，紧贴画布；关掉时收成 44px 书脊。不占 `01–04` 的编号，列头用「表图标 + 结果」与四个视图面板区分。
- **版式**: 同 A 的账页，字号降半号(12.5)以适配 420。
- **代价**: 420 是硬上限，8 列照样滚；与概览抢宽度预算(AI 一开就要按 LRU 收书脊)；画布只剩 500；结果长期占着一列，但只在一部分时间有用。

### 对比

| 维度 | A 画布锚定卡 | **B 底部抽屉** | C 右侧列 |
|---|---|---|---|
| 表格可用宽度 | 560 | **1240(整窗)** | 420 |
| 8 列表格 | 横向滚，只能看 4 列半 | **全部可见** | 横向滚，看 3 列多 |
| 字号是否受画布缩放影响 | 会(0.8 → 9.6px) | **不会** | 不会 |
| 结果多张并存 | 竖向堆叠，挤 | **页签** | 列内页签 |
| 与分支的空间关系 | 强(贴在末端) | 中(折角 + 定位) | 弱(靠链条) |
| 位置是否可预测 | 否(三种落点规则) | **是(固定底部)** | 是(固定列位) |
| 占用画布 | 560×296 起 | 304 高 | 420 宽 |
| 需要改公共容器 | 否 | 是(071 抽屉壳 + 082 偏移) | 是(076 停靠区 + 宽度预算) |
| 实现成本 | 小 | 中 | 中 |

**推荐 B。** 三条审计事实指向同一件事: 结果表的核心问题是**它被当成了画布上的一个物体，而不是一份要读的数据**。宽度、字号、位置三件事只有在「结果不属于画布坐标系」之后才能同时解决。A 最小但天花板明显；C 把同一块 420 的窄屏从画布搬到了停靠区，宽度问题原地不动，还多占一列常驻空间。

## 4. 表格规范(三案共用)

| 项 | 取值 | 理由 |
|---|---|---|
| 表头 | 32 高、11px、`--muted-foreground`、下沿 1px 22% 墨、吸顶 | 一条实线定住表头，比整格边框安静 |
| 数据行 | 30 高(A: 32)、13px(A/B)/12.5px(C)、88% 墨、下沿 1px 8% | 正文必须比表头深；行高给中文呼吸 |
| 竖线 | **不画** | 竖线把表切成一格格盒子；对齐由数字与右缘完成 |
| 行号槽 | 34(A)/44(B)/30(C)，mono 10.5，`--muted-fg-3`，右对齐 | 报错时能说「第 5 行」；也是账页的页码 |
| 数值列 | 右对齐、mono、`tabular-nums`、列宽按最长值 + 24 封顶 150 | 小数位对齐才能比大小 |
| 数值判定 | 去空白后可被 `Number()` 解析，且不含 `¥$€%,` 等符号；**只用来决定对齐** | 不做格式化，避免把 `1,200` 改写成 `1200` |
| 文本列 | 左对齐；按前 50 行 + 表头取样，封顶 240(宽表 320) | 让长文本有机会占宽，标题不缩成 `销...` |
| 余量分配 | 最后一列吃剩余宽度(文本左对齐 / 数值右对齐) | 列少时表铺满容器，不留半张空页 |
| 空值 | 12×1px 短线(26% 墨)，不写字符，**也不再加页脚图例** | 空白分不清「空值 / 未加载」；`—` 会被当成内容复制。页脚只为图例占 26px 不划算 |
| 截断 | 计数写 `前 500 行`，**不写 `500 行`**；悬停该计数给出完整说明(`resultTruncated`) | `totalRows` 是预览行数(`parseCsvString(…,500)` 后 `rows.length`)，写 `500 行` 会被读成总数 |
| 滚动 | 垂直/水平都用应用的 `ScrollArea`(Radix)，不用原生 `overflow-auto` | 与日志面板、命令面板同一条滚动路径，滚动条外观一致 |
| 复制 | 一个分体按钮: 主键复制 CSV，箭头展开 `CSV / Markdown`；成功后原地变「已复制」3 秒。提示走应用 `<Tooltip>`(不是原生 `title`) | 少一次解码；格式名写全；气泡的延迟/尺寸/位置与抽屉里其他图标按钮一致 |
| 悬停 | 整行 4% 墨底；行内不出现按钮 | 表格是读的，不是操作的 |
| 斑马纹 | 不做 | 细横线已经足够分行，再加底色是两套节奏 |

**显示不改数据**是这一节的底线: 对齐、等宽、空值标记、列宽都是排版；单元格文本按原字符串渲染，复制出去与屏幕上一字不差(空值标记不参与复制)。

## 5. 实施要点(实际落地)

1. **抽公共抽屉**: `components/layout/BottomDock.tsx` 接管高度、上沿拖拽、最大化与 `--bottom-dock-height`(替代 `--log-drawer-height`，`FlowPanel` 两处托盘偏移同步改名)。`LogPanel` 新增 `embedded` 模式: 不再自绘 fixed 壳、不画上沿手柄、不显示标题与最大化/关闭(dock 的页签栏承担)，**保持挂载**以便切页签后沿用过滤条件与滚动位置。
2. **页签**: 由调用方(App)构建 `tabs`，**日志固定第一个**;结果按分支依次 `result:0`、`result:1`。旧页签指向已消失的分支时回落到第一张结果。
3. **结果状态**: `ResultPreview` 增加 `steps: string[]`(分支步骤名)，`runPipeline` / `useRunFromStep` 同时填 `label`(保留兼容)。不新增后端命令。
4. **表格**: `modules/results/ResultTable.tsx`(纯展示) + `modules/results/ResultsPanel.tsx`(`ScrollArea` 包表格，无页脚) + 同文件导出的 `ResultMeta`(链条/计数/复制) + `modules/results/lib/resultTable.ts`(数值列判定、步骤编号剥离、CSV/Markdown 文本)。
5. **画布**: 删除 `ResultTableNode` 与 `usePipelineLayout` 里的结果节点注入;`FlowPanel` / `HomeView` 不再接收 `resultPreview`。**画布折角没有实现**(见 §8)。
6. **入口**: 执行产生结果 → `openResults(tabId)` 打开结果页签(后台标签页只存不弹);`Alt+R` 开关结果页签、`Alt+Q` 开关日志页签、查看菜单的「日志」仍落在日志页签。
7. **高度自适应**: 切到结果页签时，抽屉按 `resultPanelHeight(行数)`(5 + 32 + 32 + 行×30，**8 行封顶**)长高，只长不缩——用户拖过的高度不会被抢走；500 行预览因此不会被拉成整屏。
8. **面板切换**: 页签用 `role="tablist"` + `role="tab"` + `aria-selected`，按钮直接切页；行内左起「页签 → 1px 竖分隔 → 当前面板的工具 → 最大化/关闭」。
9. **i18n 新 key**: `results`、`resultRowsCols`、`resultRowsColsTruncated`、`resultTruncatedRows`、`resultTruncatedShort`、`resultEmptyCells`、`resultEmpty`(zh/en + `types.ts`)。

### 5.1 测试

- `resultTable.ts`: 数值判定(`1,200` / `¥12` / `N/A` / 全空列)、空值计数、CSV 引号与 Markdown 转义。
- `ResultsPanel`: 链条与计数、空值短线、截断写「前 500 行」、复制 CSV 与菜单里的 Markdown。
- `BottomDock`: 日志第一个页签、切页签时日志体仍挂载(只是 `hidden`)、关闭回调、关闭时不渲染。
- 回归: `LogPanel` 13 例、`SettingsDialog` 快捷键 12 → 13 项。

## 6. 明确不做

- **不加排序、筛选、列显隐、单元格编辑**。结果预览是只读快照，加这些会把它变成第二个数据编辑器。
- **不做结果导出**。`output` / `to` 步骤已经是导出路径，预览不重复承担。
- **不改 500 行预览上限**。它由 `parseCsvString` 的第二个参数决定，改大要重算内存与渲染预算，与本设计无关。
- **不改连线手势、Handle 显隐、`autoConnect=false`**(027 红线)。
- **不做「结果未连线」之类的提示**(多分支是刻意设计，027 红线 ②)。

## 7. 结论与遗留

1. **默认高度 260，结果页签自动长到内容高(8 行封顶，6 行 = 307)**。若实际常看 20 行，可把封顶从 8 调到 10~12，不要取消封顶。
2. **画布折角未做**。替代路径是「结果产出即打开结果页签」——它保住了「跑完就能看见结果」这件事，只是不带空间归属。若后续要把归属感补回来，再做折角，不要回退成画布内的结果卡片。
3. `ResultPreview.label` 现在只作兼容保留(没有任何 UI 读取);确认无外部依赖后可删。
4. `--log-drawer-height` 已全部改名为 `--bottom-dock-height`，`082` 的步骤托盘因此跟随结果页签一起上移(这是想要的行为)。
