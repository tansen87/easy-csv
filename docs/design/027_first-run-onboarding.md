## 0. 结论速览

**一句话诊断**：Easy CSV 的「入门门槛」不在于功能不够，而在于 **打开文件之后画布上什么提示都没有** —— 所有前进路径（命令面板、日志、AI、数据概况）默认全部关闭（日志面板唯一会自己打开的时刻是「执行时」，见 §4.3）。新用户卡在「第二个动作从哪开始」，而不是卡在操作本身。

**本次讨论已定的两条红线**（详见 §3.2 / §10）：

1. **连线手势不改。** 右键拖拽连线、右键划过切割、空格/中键平移、左键框选一律保持原样。
2. **不做自动连线，也不做「未连接」警告。** 本项目刻意支持**多分支**：新添加的节点默认自成一条分支，执行时直接吃原始输入（`buildExecutionBranches` 对无入边节点各自成支）。因此「加了命令不连线」**不是缺陷，是特性**，任何引导都不得把它当成错误，也不得替用户连线。

**建议的解法顺序**（按「投入产出比」排序）：

| 优先级 | 编号 | 方案 | 一句话说明 | 主要产物 |
|--------|------|------|-----------|----------|
| **P0** | 4.1 | **示例数据 + 示例管道** | 一键「看看示例」，直接得到一个已经跑通的 3 步管道 | 内置示例 CSV + 内置模板 |
| **P0** | 4.2 | **「第一个步骤」引导** | 空管道时画布出现一张纯文字引导卡 + 命令面板内的就地提示，**全部指向命令面板这唯一入口**（不做假节点） | 画布引导卡 + 面板提示条 |
| **P1** | 4.3 | **执行完成的顶部 Toast** | 执行结束发一条顶部 Toast（带「查看结果」）；日志面板自动打开、步骤失败红标都已是现状，**不做成功标记** | 扩展 Toast 组件 |
| **P1** | 4.4 | **内置模板库 + 帮助中心「5 分钟上手」** | 模板库不再空着；帮助中心从「键位表」升级成入门教程 | 内置模板 + 帮助文档 |
| **P1** | 4.5 | **命令面板「常用」分组** | 61 个命令 14 个分类对新手是压迫性的，先给 8 个高频的 | `data/commands/` |
| **P1** | 4.6 | **连线手势的教学（不改交互）** | 只把现有右键手势写到画布上让人看见 | 画布手势卡 |

**需要你拍板的 5 件事**，见 §8。

### 一句话总结用户的感受

> 「我打开了文件，然后……就不知道干什么了。我点了一个命令，画布上多了一个框，按下执行，好像跑了，但我没看到结果。」

注意这句话里的三个卡点：**不知道在哪加操作**（A）、**不知道入口藏在哪**（B）、**跑完看不到结果**（E）。**没有一个是「节点没连线」。**

## 2. 问题归因：五个断点（含一条刻意保留的「非缺陷」）

| 断点 | 问题本质 | 为什么严重 |
|------|---------|-----------|
| **A. 空画布无引导** | 应用在「用户最需要帮助的一刻」保持了沉默。表格节点是唯一锚点，却没有承担入口职责 | 用户会停在第二个动作上 |
| **B. 入口全隐藏** | 前进路径（命令面板 / 日志 / AI / 数据概况）默认全关（日志只在执行时自动打开），且都以「纯图标 + Tooltip」呈现 | Tooltip 只有 hover 才出现 → **不可发现 = 不存在**；「执行」置灰且无解释 → **沉默的死路** |
| **D. 连线手势反直觉**（**已决定不改**） | 自定义右键拖拽替代了通用手势，且起手必须落在操作节点上 —— 空管道时无从起手 | 用惯节点编辑器的人确实会先试左键；但**改手势会破坏老用户肌肉记忆，收益与风险不成正比**。决策：不动任何交互，只把真实手势写进画布（§4.6） |
| **E. 缺完成反馈** | 日志面板在执行开始时就会自动打开（**已实现**），结果一直看得到；但跑完**没有任何「完成」确认**，只有进度条 5 秒后静默消失 | 长管道跑完用户不知道结束了，容易重复点执行 —— 「我执行了但什么都没发生」 |
| **F. 求助路径缺失** | 帮助中心只有键位表（29 行），模板库对新人是空列表 | 用户卡住时没有任何自助手段 |

### 刻意保留、**不修**的一项：新节点默认不连线

`App.tsx:347-352` 里 `autoConnect = false` 是默认值，这常被误读成 bug。实际上它服务于本项目的核心能力 —— **多分支**：

- `buildExecutionBranches`（`hooks/execution/buildBranches.ts`）对**没有任何入边**的节点，会把它们各自当成独立分支（`edges.length === 0` 时直接 `steps.map(step => [step])`），每个分支都直接以输入文件为上游。
- 所以「打开文件 → 加 3 个互不连线的命令 → 执行」是**合法且常用**的用法：三条分支并行跑，一次拿到三份结果。
- 如果改成自动首尾相连，多分支就没了 —— 这与项目定位冲突。

**结论：这不是断点，是要守住的设计。** 本方案所有环节都不得把它当成错误（不得自动连线、不得给「未连接」加警告徽标、不得在引导文案里暗示用户必须连线）。

> 唯一需要补的是**认知层面**：用户需要知道「新节点默认自成一条分支」以及「想串起来该怎么连」。这由 §4.2 的画布引导卡 + 命令面板提示条与 §4.6 的手势卡承担。

## 3. 设计目标与原则

### 3.1 可验证的目标

| 目标 | 衡量方式（建议） |
|------|-----------------|
| 新用户能在 **60 秒内**看到一个跑通的管道 | 从「打开示例」到日志出现结果，无需任何文档 |
| 打开文件后 **100% 有可见的下一步入口** | 画布空态必现引导（可用「重新显示引导」复位验证） |
| 「新节点和输入数据是什么关系」不再需要猜 | 引导卡与命令面板提示条明写「自成一条分支」，手势卡明写「怎么串起来」 |
| 引导**只打扰一次** | 关闭后写入 localStorage，不再出现；设置页可复位 |
| **多分支能力零回归**（红线） | 连续添加 N 个互不连线的节点 → 执行时各自成支、全部产出结果，且画布上**没有任何**「未连接」类提示 |

### 3.2 原则（写进代码评审清单）

1. **渐进式披露，不做多页向导。** 不搞覆盖全屏的 N 步 Wizard。每一步引导都能「直接跳过」，且跳过后不再重来。
2. **就地引导 > 弹窗。** 提示出现在用户当时正在看的地方（画布中央、节点旁、置灰按钮上），而不是一个需要读三行的对话框。
3. **每个引导必须落到一个真实动作上。** 能一键完成的就给按钮；只写文字说明的引导一律不接受。
4. **不动任何既有交互手势。** 所有改动都是「在原有路径之上加提示」，不是「换掉或新增一条操作路径」。连线、切割、平移、框选的手势全部保持原样（§4.6）。
5. **尊重多分支模型（新）。** 管道是 DAG，不是线性链。新添加的节点默认自成一条分支，执行时与其它分支并行产出结果。**任何引导、提示、校验都不得把「节点未连线」当成错误，也不得自动替用户连线。**
6. **引导本身要可复位、可关闭、可国际化。** 所有文案进 `i18n/translations/{en,zh}/`，中英同时补齐（缺 key 会直接编译失败，见 `i18n/translations/types.ts`）。

## 4. 方案分层

### 4.1 【P0】示例数据 + 示例管道：「先看一个跑通的例子」

**这是投入产出比最高的一条。** 新手最大的障碍不是「不会操作」，而是「不知道这个东西能干什么、长什么样」。给一个**已经跑通的完整管道**，比任何文字教程都有效。

**做法**

1. **内置一份示例数据**（约 200 行合成销售数据，含日期/地区/品类/金额/数量五列，故意留 2~3 处脏数据以便演示清洗）。
   - 实现：Rust 侧用 `include_str!` 嵌入（约 10 KB，不引入打包变更），落到 `<数据目录>/samples/easy-csv-sample-sales.csv`，**仅在文件不存在时写入**（幂等），新增命令 `ensure_sample_data() -> String`（返回绝对路径）。
   - 备选：纯 Rust 程序化生成，避免往仓库塞数据文件。二选一，见 §8-Q1。
   - 注意：`src-tauri/.gitignore` 排除了 `*.exe`，但 `.csv` 不受影响；同时要把文件登记进 `docs/AI/INDEX.md` 以免 `pnpm check:index` 失败。

2. **内置模板**（`PipelineTemplate` 形状，TS 常量，放 `src/data/templates/builtin.ts`）：
   - `builtin:demo-sales` — **示例：清洗销售数据**（过滤坏行 → 去重 → 分组汇总），这是唯一的「示例」。
     ⚠️ **示例管道里不放导出步骤（`to` / `output`）**。理由：示例是**自动执行一次**的（见第 4 条），带导出步骤会在用户的磁盘上凭空写出文件 —— 这是一个不该有的副作用。导出的教学放在「5 分钟上手」第 ⑤ 节里由用户自己动手。
   - `builtin:quick-clean` — 快速清洗（去重、去空行、规范化列名）
   - `builtin:group-summary` — 按列分组汇总
   - `builtin:join-two-tables` — 两表连接
   - `builtin:split-by-column` — 按列拆分多文件
   - 内置模板与用户模板在 `usePipelineTemplates` 里合并：`[...BUILTIN_TEMPLATES, ...userTemplates]`，对话框分「内置 / 我的」两组（内置项不提供删除/重命名，提供「复制到我的模板」）。

3. **入口**（三处，同一个 action，见原型 01）：
   - 空状态新增第 1 张卡（放在「打开文件」左边）：**「看看示例 · 30 秒」**
   - 帮助中心顶部按钮
   - 命令面板（`Ctrl+K`）动作组里加一项「打开示例管道」

4. **示例打开后的状态**必须「一眼看懂」，因此 `applyBuiltinDemo()` 要一次性完成：
   - 新建标签页 → 加载示例 CSV → 应用示例管道（3 个节点，**显式连线成一条链**）→ **自动执行一次** → `fitView` → 日志面板（执行时会自动打开，复用 `runPipeline.ts:102` 的既有行为）里就是结果。
   - **只弹一条 Toast，不要弹两条**：把示例的引导语并进 §4.3 的完成 Toast 文案里，例如
     `示例管道执行完成 · 3 个步骤 · 0.8s · 这是一条串好的管道（也可以不连线，让每个节点各跑一条分支）`。
   - 自动执行这个动作**只在这一处**使用，且不写任何输出文件（第 2 条已保证示例管道不含导出步骤）。

> **为什么它排第一**：它同时解决断点 A 和「认知层面」的缺口 —— 用户第一次看到的画布就是「有连线的多节点」，既建立了数据流的心智模型，又顺带示范了「连线是可选动作」。

### 4.2 【P0】「第一个步骤」引导（**收敛到命令面板这唯一入口**）

**场景**：用户自己打开了文件，管道为空。此时画布中央只有孤零零一个表格节点。

**先确认一个事实（决定了本节怎么做）**

> 添加操作在当前实现里**只有一条路**：命令面板（工具栏 `ListTree` 按钮 / `Alt+C`）或全局命令面板（`Ctrl+K`）。
> 画布右键菜单只有「粘贴」与「另存为中间结果」，**没有「在此添加操作」**（`FlowPanel.tsx:744-762` 的 `canvasMenuItems`）。

**因此引导的形态必须是「指向命令面板」，而不是在画布上另造一个入口。** 一个半透明的假节点虽然点起来很顺手，但它和真实流程是两套动作（点假节点 → 结果打开的是另一个面板），而且会误导用户期待「节点出现在这里」—— 实际落点由 dagre 自动布局决定（`pipeline/lib/layout.ts`），本来就不可预判。**这属于断档，本方案不做。**

**做法**（原型 02）

1. **画布空态引导卡**：管道为空时，在画布空白区显示一张**纯文字卡片** —— 不是节点样式、不可拖动、没有标题栏与连接点、不参与布局，只是引导：
   ```
   从这里开始
     数据已经就位。选一个操作就能开始。
       [ 添加一个操作 ]   → 打开命令面板      (Alt+C)   ← 主按钮
       [ 直接描述需求 ]   → 打开 AI 助手      (Alt+A)
       [ 先看看示例 ]     → 加载示例管道      (§4.1)
       新加的节点会自成一条分支，直接就能执行；想串起来再连线。
                                     [ 我知道了 ]  ✕
   ```
   - 三个按钮都是**真实动作**，不是文字说明。
   - 那行小字是本方案对「多分支」的**唯一交代** —— 不解释清楚，用户会以为节点没连上是坏了。
   - 关闭（或用户实际完成第一步）后写 `localStorage: easy-csv-onboarding-v1 = "done"`，之后不再出现。

2. **命令面板内的就地提示（本节的关键）**：面板打开、且当前标签页 `pipeline.length === 0` 时，在搜索框下方显示一条细提示条：

   > `选中第一个操作后，它会直接对输入数据生效（自成一条分支）`

   - 这是把教学放在**用户真正点击的那一刻**、**在唯一入口内部**，与引导卡形成「卡 → 面板 → 选中命令」的连续路径，没有断档。
   - 面板关闭或管道非空时提示条消失。
   - 组件改动很小：`CommandList.tsx` 头部加一个可选的提示槽位，由 `App.tsx` 传入一个布尔值。

3. **首次引导时让入口自己亮一下**：引导卡出现的同时，工具栏的命令面板图标做一次约 2 秒的轻微高亮/呼吸，把「卡上的按钮」与「入口在哪里」对应起来 —— 下次用户不看卡也知道去哪点。**只做视觉高亮，不改任何点击行为。**

4. **置灰的「执行」按钮加解释**：给 `MainMenu` 的「执行」按钮补 `Tooltip`——管道为空时提示「先添加至少一个步骤」，并附一行 `Alt+C 打开命令面板`。（断点 B 的最小修复，改动量极小。）

### 4.3 【P1】执行完成的反馈（顶部 Toast）

**现状（已逐行核实）**

| 事实 | 证据 | 结论 |
|------|------|------|
| 执行**开始**时日志面板会自动打开 | `hooks/execution/runPipeline.ts:102` `setShowLogPanel(true)`（配套 `setShowProgressBar(true)`） | ✅ **结果一直在视野里 —— 这条已实现，本方案从待办里删掉** |
| **步骤失败标记已经存在** | `modules/pipeline/nodes/PipelineStepNode.tsx:265-280`：`step.error` → 节点 `border-red-500/70 ring-2 ring-red-500/30` + 节点内红色错误文本；`runPipeline.ts:254` 也已 `addLog("error", …)` | ✅ **已实现 —— 不要新增任何节点标记（尤其不要加「成功标记」）** |
| 执行**结束**时没有任何完成提示 | `runPipeline.ts:287-290` 只写执行历史 + 5 秒后隐藏进度条，无 toast | ⚠️ 这是真要补的（成功、失败都没收尾提示） |
| Toast 系统本来就在**顶部居中** | `components/setting/Toast.tsx`：容器 `fixed top-0 … items-center`；单条 `fixed top-12 left-1/2 -translate-x-1/2` | ✅ 完成提示直接用 `showToast` 即可，位置天然一致 |

**做法**（原型 03）

1. **执行完成 → 顶部 Toast**：沿用现有 Toast（顶部居中），文案
   `管道执行完成 · 3 个步骤 · 0.8s`
   - **不显示行数变化**（本次修订）：每个步骤的行数在日志面板里已经有了（`0.4s · 3 行` / `0.2s · 1180 行`），Toast 里再重复一遍只是噪音。
   - 多分支时写明分支数：`3 条分支全部完成 · 0.8s`。
   - 长管道这一条尤其重要 —— 现在跑完没有任何提示，用户只能靠进度条静默消失来猜。
2. **失败时走同一条 Toast 的 `error` 态**：文案指出是哪一步失败（节点变红、日志已写错误，这些都是现状，不重复做）。失败必须比成功更显眼。
3. **给 Toast 加一个可选动作**（唯一的组件改动）：`ToastProps` 增加 `action?: { label: string; onClick: () => void }`；完成 Toast 带 **`[查看结果]`**（打开日志面板并滚动到最后一个步骤）。
   - **不带「打开数据概况」**：数据概况是可选深入动作，不属于「执行完成」的默认下一步；需要它的人自己从「更多面板」里开。

**已删除（本次讨论结论）**

- ❌ **不做「每步成功标记」**：不在步骤节点上加 ✓。一条管道本来就可能有很多节点，满屏绿点会让工作流看起来更复杂；成功是默认预期，不需要额外装饰。失败已经有红框 + 红字块（现状实现），这条已经够了。
- ❌ **「结果节点 = 视觉终点」整条不做**：不做结果节点的绿色描边 / 外发光，不做节点内嵌的摘要条与按钮。结果统一通过「自动打开的日志面板 + 顶部 Toast」呈现，画布上不额外装饰任何节点 —— 结果节点就是普通节点样式，只有标题和内容不同。
  - ✅ **例外（§11.3，用户实测后修订）**：「查看结果」动作会把画布**平移**到结果节点居中（`setCenter`，保持用户缩放）—— 只动视角，不做节点装饰，也不做 `fitView`（那会改缩放）。
  - 代价（知情即可）：结果节点如果在视野外，用户得自己平移画布去找。因为日志面板已经自动打开、结果数据就在眼前，这个代价可以接受。
- ❌ 结果节点上的「查看」按钮 —— 属于上一条，一并删除。

### 4.6 【P1】连线手势的教学（**不改交互**）

> **决策（本次讨论结论）：连线手势一律不改。** 不新增左键连线、不改 Handle 显隐、不加连接点呼吸动画、不调整 `connectionMode` / `panOnDrag` / `selectionOnDrag`。`nodes/TableNode.tsx:167-198` 的 Handle 保持 `opacity:0` + `pointerEvents:"none"` 原状。本节只做「让用户知道手势存在」。

**先认清一件事：这不是「第一步连不上」的补救。**

实测右键连线的起手条件（`FlowPanel.tsx:441-459`）：

```ts
const clickedNode = getNodeAtPosition(e.clientX, e.clientY);
if (clickedNode && clickedNode !== "table-node") {
  startConnect(clickedNode);   // 只有「操作节点」能作为连线起点
} else {
  startCut(e);                 // 空白处 / 输入节点上右键拖拽 = 切刀
}
```

两个事实：

1. **右键连线的起点只能是「操作节点」**，输入表格节点不能起手；
2. 因此**管道为空时右键连线无从起手**。

但这**不是缺陷**：新节点本来就可以不连线自成一条分支（§2）。所以不需要「补一条起手路径」，只需要让用户知道「连线这个动作存在、以及怎么做」。

**本节只做两件事**（纯展示层，零交互改动）

1. 画布右下角常驻「画布手势」小卡（见 §4.2 第 4 条），把四条真实手势写清楚，首次进入自动展开一次，之后折叠成 `?` 圆钮：
   - 右键按在**操作节点**上拖到目标节点 → 连线
   - 右键在空白处按下并划过 → 切掉连线 / 节点
   - 空格 + 左键 或 鼠标中键拖拽 → 平移画布
   - 左键拖拽空白处 → 框选
2. 画布引导卡、命令面板提示条与「5 分钟上手」里各写一句：**不连线也能跑（自成一条分支），连线只是把两步串起来。**

**不做的**（写进评审红线）

- Handle 显隐 / 命中区域改造 —— 保持原状
- 左键从连接点拖出连线 —— 不实现
- 连接点呼吸动画 / 高亮 —— 不加
- 把右键连线改成左键、或改成「点两个节点即连线」—— 不实现
- `panOnDrag` / `selectionOnDrag` / `connectionMode` / `rightClickMode` 的任何调整 —— 不动

**回归红线**：本次改动不应触碰 `FlowPanel.tsx` 里任何手势相关代码（`handleCutStart` / `handleCutMove` / `handleCutEnd` / `handlePanelContextMenu` / `useConnectGesture`）。`FlowPanel.tsx` 的唯一改动是渲染 §4.2 的覆盖层组件。

## 8. 开放问题（需要你拍板）

**Q1. 示例数据怎么来？**
- (a) 仓库内置一份 `.csv`（Rust `include_str!`，约 10 KB）→ 数据可控、可设计「脏数据」教学点
- (b) 纯 Rust 程序化生成 → 仓库不增文件，但数据「假」得比较均匀，教学点要靠代码硬编
- 倾向 **(a)**。

**Q2. 「第一个步骤」的引导用哪种形态？**（本次修订新增；幽灵节点已按讨论结论删除）
- (a) **画布空态引导卡 + 命令面板内就地提示**（§4.2 的写法，我的倾向）→ 全部指向命令面板这唯一入口，路径连续无断档；面板提示条落在用户真正点击的那一刻

- (c) (a) + **画布上保留一个纯装饰、不可点击的虚线槽位**（`pointer-events:none`），只用来预示「节点会落在这片区域」→ 保留了空间暗示，但落点本来由 dagre 决定、并不精确，可能反而造成误解

- **不做自动连线，也不做任何「未连接」提示（本次讨论结论，红线）**：不加 `shouldAutoConnect`、不加 `autoConnect` 相关配置开关、不给孤立节点加琥珀徽标或「一键接入」、不弹「是否连接到上一步」的询问。**多分支是本项目的刻意设计** —— 新节点默认自成一条分支（`buildExecutionBranches` 对无入边节点各自成支），自动连线会把这项能力抹掉。详见 §2。
- **不修改任何连线手势（本次讨论结论，红线）**：不恢复左键连线、不改 Handle 显隐与命中区域、不加连接点呼吸动画/高亮、不调整 `connectionMode` / `panOnDrag` / `selectionOnDrag` / `rightClickMode`。`TableNode.tsx:167-198` 的 Handle 保持 `opacity:0` + `pointerEvents:"none"` 原状。详见 §4.6。

- **不做「每步成功标记」（本次修订新定）**：不在步骤节点上加 ✓ / 绿色角标。一条管道本来就可能有很多节点，满屏绿点会让工作流看起来更复杂；成功是默认预期，不需要额外装饰。**失败标记已经存在**（`PipelineStepNode.tsx:265-280` 的 `step.error` → 红框 + 红字块），因此整条「每步标记」都不需要做。详见 §4.3。
- **不做「结果节点 = 视觉终点」（本次修订新定，§11.3 局部修订）**：不做结果节点的绿色描边 / 外发光、不做节点内嵌摘要条与按钮、不做结果节点上的「查看」入口。结果统一由「自动打开的日志面板（现状）+ 顶部完成 Toast」呈现；唯一例外是「查看结果」会把画布**平移**到结果节点居中（不改缩放、不加装饰），见 §11.3。
- **不重复实现「日志面板自动打开」**：`runPipeline.ts:102` 已实现，本方案不得改动这一行为。
- **不做首启引导屏 / 「三扇门」式选择页（本次修订新定）**：不做覆盖首启的引导屏，也不因此简化现有空状态。入门路径统一由 §4.1 的「看看示例」主卡承担（原 §4.7 方案与原型 04 一并删除）。

- **不做新手任务进度条 / 成就系统**。

### 与本文档不一致的地方（实施时改了，都是有理由的）

1. **组件位置**：引导层落在 `src/components/onboarding/FirstStepGuide.tsx`，不是本文写的 `src/modules/pipeline/overlays/`。原因：`modules/data-preview` 引用 `modules/pipeline` 会触发 `local/no-cross-module-imports`（既有代码已有同类告警，不值得再加一条）。同时**改为在 `HomeView` 渲染这个覆盖层，`FlowPanel.tsx` 一行都没改** —— 比本文档的要求更严格：整条手势链路（`handleCutStart`/`handleCutMove`/`handleCutEnd`/`handlePanelContextMenu`/`useConnectGesture`）零改动。
2. **示例数据的脏值必须是「空」而不是 `N/A`**：`xan groupby` 遇到非数值会直接中止（实测报 `cannot safely cast Bytes("N/A") … to type "number"`），而示例管道是**自动执行**的 —— 新用户第一次看到的就会是报错。所以脏数据统一为空值（4 处空金额 + 1 处空地区 + 2 行完全重复，共 219 行）。
3. **`groupby` 的表达式必须写成 `sum(col("金额")) as "金额合计"`**：裸写 CJK 列名（`sum(金额)`）**解析失败**（`expected func_arg`），而 `sum("金额")` 会被当成**字符串字面量**（报错 `cannot safely cast String("金额")`）。只有 `col("…")` 才是列引用 —— 这与 `initialParams.ts` 里 `col("${col}")` 的写法一致。
4. **示例数据的字节被钉住**：`include_str!` 嵌入的是**工作区字节**，所以 `.gitattributes` 里加了 `src-tauri/samples/easy-csv-sample-sales.csv text eol=lf`，否则 Windows 上 `core.autocrlf` 检出成 CRLF 会改变发给用户的内容并让 `embedded_sample_has_expected_shape` 在 CI 上挂掉。
5. **示例的引导语并进完成 Toast，且不显示行数变化**：`示例管道执行完成 · 3 个步骤 · x.xs · 这是一条串好的管道（…）`。
6. **完成 Toast 的自动关闭时间放宽到 8 秒**（默认 5 秒），否则「查看结果」按钮来不及点。

### 11.1 修复记录：示例自动执行失败（2026-09-30，用户实测报回）

**现象**：点「看看示例」后自动执行失败，报
`xan search: '金额' does not exist as a named header in the given CSV data.`（`groupby` 同理），但**手动点执行没问题**。

**根因（两个叠加）**

1. **自动执行触发得太早**：`.snapshot` 里本来就带着 `inputFile` 和管道，我原来的守卫 `tab.inputFile && tab.pipeline.length > 0` 在 `setTabs()` 之后的**第一次渲染**就满足了 —— 那时 `loadCsvData` 还没跑完，tab 的 `defaultDelimiter` 还是空的。而 `resolveRunDelimiter()` 的规则是 `tab.defaultDelimiter || 全局默认分隔符`（`hooks/execution/resolveDelimiter.ts`），于是用了**全局默认分隔符**而不是这份 CSV 真正的逗号。
2. **分隔符错了就正好长这样**：执行时输入是**走 stdin** 的（`pipeline.rs` 把 `File::open(effective_input)` 接到子进程 stdin），`-d` 由首条命令带上。分隔符一旦不是逗号，整行表头被解析成**一个字段**（`日期,地区,品类,金额,数量`），于是 `-s 金额` / `groupby 地区` 都找不到表头。

用真实 xan 逐一复现确认：`search --select 金额 --non-empty -d ';'` 与 `groupby 地区 … -d ';'` 打出的**正是用户看到的那两句话**，逐字一致。

**修复（两道保险，都做了）**

- `src/data/templates/builtin.ts`：示例模板**钉住自己的分隔符** `defaultDelimiter: ","` —— 数据是我们自己写的，格式只有我们知道。其它模板**不钉**（它们跑在用户自己的文件上，必须用 tab 检测出来的那个）。
- `src/app/App.tsx`：自动执行的触发从「ref 标记」改成 **`loadCsvData` resolve 之后才设置的状态** `demoReadyTabId`，保证运行时 tab 的 `defaultDelimiter` / `headers` / `data` 都已就位。

**顺带修掉的另一个同源 bug**：模板对话框里对示例模板点「使用」时，`handleApplyTemplate` 会把占位符 `{{easy-csv-sample}}` **当文件名**交给 `loadCsvData`，开出一个空标签页。现在抽了 `openSampleTemplate(template)` 共用，并在 `handleApplyTemplate` 里用 `needsSampleData(template)` 判断 —— **按占位符判断而不是按模板 id**，这样用户「复制到我的模板」出来的副本（仍然带着占位符）也走同一条路。

**回归保护**：`builtinTemplates.test.ts` 新增「示例钉住分隔符 / 其它模板不钉」「`needsSampleData` 对副本与已替换的模板都判断正确」。

### 11.3 「查看结果」把结果节点平移到画布正中（2026-09-30，用户反馈）

**问题**：完成 Toast 的「查看结果」只是把 Toast 关掉（顺带开了日志面板）—— 用户点了它，画布却纹丝不动。管道一长，产出结果的节点在视口外，用户得自己一路找过去。

**做法**：Toast 动作 = `setShowLogPanel(true)` + `focusResultNode()`。后者取**当前管道最后一步**（结果落点），用 ReactFlow 的 `setCenter(nodeCenter, { zoom: 当前缩放, duration: 400 })` 平移画布把该节点放到正中。

- **是平移不是 `fitView`**：保持用户的缩放不动。`fitView({ nodes: [...] })` 会把视口塞满那个节点，缩放被强行拉高，反而打断用户的空间感。
- **没有画布实例 / 没有该节点时直接 no-op**（首次渲染前 `reactFlowInstanceRef.current` 还是 null）。
- 走 `useExecution` → `runPipelineDeps.focusResultNode` 注入，与 `setShowLogPanel` 同一条路。

**回归保护**：`tsc` / 全量 vitest（505）/ eslint 0 error / `check:index`。

### 11.2 示例改为「逐步骤装出来」（2026-09-30，用户反馈「一点进去就是一堆操作」）

**问题**：点「看看示例」后，3 个节点**瞬间全部出现**。用户看到的是**成品**，看不到**它们是怎么被加进去的** —— 而这恰恰是新手最需要理解的一件事（添加操作的唯一入口是命令面板）。§4.1 原本只承诺「得到一个跑通的管道」，但没承诺「看得懂它是怎么被装出来的」。

**做法**

1. **示例的步骤逐个出现**：新建标签页时管道**留空**（只加载数据），随后**用户每点一次「下一步」加一步**（同时加入对应的边）。最后一步到位后按钮变成 **「跑一遍」**，点了才执行。
   - 用 `setTabs` 直接写入，**不走 `updateTabPipeline`** —— 装示例不是用户编辑，留 3 条撤销记录只会是噪音。
   - **每次打开示例都这样回放**。曾用 `!onboarding.seen` 限定「只第一次」，结果用户测试过一次后，标记已被消费 —— 此后点「看看示例」永远拿到的是成品 + 自动执行，**新的交互根本没机会出现**（2026-09-30「目前还是自动的」即此因）。点「看看示例」本身就是明确要求看演示，所以每次都播。
2. **每一步配一条「这一步是怎么来的」说明**：画布顶部一条 pill，形如 `2/3 · 再点 dedup → 去掉完全重复的行`，右侧带 **「下一步」/「跑一遍」** 与 **「跳过」**。
   - **节奏完全交给用户**（第三次调整）：先用定时器（950ms → 2.6s）自动推进，用户仍反馈「还是太快」—— **没有哪个固定节奏能适合所有读者**，所以定时器整个删掉，改为纯点击驱动。
   - **pill 全程可见**（含第 0 步）：计数器表示「这次点击会装上第几步」（1/3 起）。曾把 `revealed === 0` 视为「还没东西可说」而不渲染 —— 点击驱动后这正是用户开始的地方，不显示就没人知道从哪点起。三步装完后文案换成「三步都在画布上了，点「跑一遍」看结果」。
   - 按钮只有**一个**：还有步骤时是「下一步」，最后一步到位后变成「跑一遍」（点了才执行）。不会出现点不动的死按钮。
   - 「跳过」即立刻补全管道并开跑。
   - 说明文案与示例步骤**放在一起**（`builtin.ts` 的 `demoRevealCaptions`），并由单测卡住「一条步骤一条说明、顺序一致」。
   - 三条说明都点名了命令（`search` / `dedup` / `groupby`），这样用户学到的是**配方**（打开命令面板 → 点某条命令），而不是「这里会变出节点」。
3. **步骤节点加入场动画**：`index.css` 新增 `node-enter`（0.28s 淡入 + 轻微上移缩放），`PipelineStepNode` 挂载时播放一次。这不只服务示例 —— **用户自己从命令面板点出来的节点也会「跳」一下**，正好补上「我点了他没反应？」的疑虑。
   - 节点在普通编辑（重排、改参数）中保持同一身份，**不会重播**；切到另一个标签页因 id 不同会重挂载，表现成一次轻量过渡。
4. **装配期间的生命周期**：`demoReveal` 三态 —— `steps`（逐步装配，由按钮推进）→ `running`（显示「三步装好了，正在跑一遍…」）→ 清空（等 `isExecuting` 落回 false，即示例那次执行结束）。
   - ⚠️ 坑（即使后来定时器删了也值得记住）：`tabsHook` 每次渲染都是**新对象**，放进 effect deps 会把定时器/回调反复重置。凡涉及它的 effect 一律取稳定别名 `setTabsDirect = tabsHook.setTabs`。

**回归保护**：`OnboardingGuide.test.tsx` 新增「pill 显示说明与进度并触发跳过 / 「下一步」推进一步 / 最后一步后按钮文案变为「跑一遍」/ running 阶段无计数 / `reveal` 为 null 时不渲染」；`builtinTemplates.test.ts` 新增「说明条数与步骤数一致、顺序一致、每条都点名对应命令」。

**实现要点**：推进逻辑只有一个 `handleAdvanceDemoReveal()` —— 还有步骤就装一步，装完了就 `setDemoReadyTabId` 触发执行；按钮的文案随 `index/total` 切换。没有定时器，也就没有「点快了会连跳两步」这类时序问题。

**教训（务必记住）**：给引导类功能加「只出现一次」的门槛之前，先想清楚**这个标记什么时候会被消费**。如果它在你自己测试的第一轮就被置位，那么后续所有迭代你都看不到新行为，而且会误以为改的东西没生效。
