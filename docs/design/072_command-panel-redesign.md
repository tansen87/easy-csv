## 2. 方向（unslop 五条）

- **产品**：把 xan 的 CSV 操作串成可视化管道；这个窗是**从 61 个操作里挑一个**的目录，不是功能展示页。
- **性格**：准确、像工具、不冷 —— 一本查得快的目录。
- **世界**：账本与索引卡（033/040 已定）。**页签 = 吸顶的分组头，条目 = 行**；不另开目录栏——那是导航，不是目录。
- **时刻**：真正的"物"是命令名本身 —— 等宽的 `filter`、`groupby` 就是这套界的质感，不需要图标或插画。
- **签名**：分组头上的 `01`–`14` 等宽序号，与设置页分组序号（040）、画布步骤卡 `01/02/03`（033）同一套编号系统。

## 3. 形态决策：为什么是「更大的浮动面板」，不是对话框、也不是抽屉

| 选项 | 否决/采纳理由 |
|---|---|
| 模态对话框（设置那种） | 选完一个操作要立刻回画布继续搭；模态会打断。且 `Ctrl K` 命令面板（053）已经是模态检索的形态，两者不该同形 |
| 左侧抽屉（日志那种） | 抽屉吃画布宽度且常驻；挑操作是**间歇**行为，用完就关 |
| **固定位浮层（采纳，260 × 窗口高 − 44）** | 必须能与画布共存、又要能一键关掉；**不拖、不记忆坐标**（见 §12.3 第 12 条：可拖的含义是"会跑"，对目录没有价值，还会让下一次打开落在上次的旧位置）。宽度从 520 收到 **260**（两行排版 + 删掉左栏）；高度不再写死 540，而是**顶在标题栏下方（36+6）、底距窗口 8**，等于把整条窗口高度都给目录，窄而高 |

**与 `Ctrl K` 的分工**（必须保住）：目录 = **被看见**（我不知道 xan 能做这个），搜索 = **被找到**（我知道它叫什么）。所以这个窗不做成"只有搜索框的 palette"，而是目录条 + 全量列表。

## 3.1 位置：为什么是「左缘 · 垂直居中」

右上角是**会变的停靠带**：AI 面板 360（开历史时 520）+ 数据预览 320，全开时右侧 680px 恒被占用（`App.tsx:281`、`:2401`）。所以任何贴右上的位置都必然与它们叠在一起；左缘是唯一不会被其它面板征用的地方。

| 候选 | 盖住什么 | 与 AI / 预览停靠 | 来源连续性 | 1024 窄窗 | 改动量 |
|---|---|---|---|---|---|
| **A 左缘 · 顶到标题栏下方（采纳，x=8）** | 输入表 + 01 步 | 不冲突（右侧 680 全空） | 弱：按钮在右上 | 8–268，占 22%；工具轨移到 280 | 小：固定 box + 轨的位移 |
| B 锚定「命令」按钮下方（右对齐 y=42） | 管道尾 + 结果表 | 完全重叠 | 强：就在按钮下 | 668–1188，贴边 | 中：要写锚点定位 |
| C 右缘 · 垂直居中（现状默认） | 管道尾 + 结果表 | 完全重叠 | 中 | 贴右缘，像停靠 | 0 |
| D 居中偏上（y=80） | 中段三步 | 不冲突 | 弱 | 252–772 | 小：改 `defaultX` |

**采纳 A 的理由**：① 选操作时你要看的是"有哪些操作"，不是"我的列长什么样"——后者在命令表单里还要再看一遍；反过来盖住管道尾部，会让人一瞬间以为步骤丢了。② 面板**贴左（x=8）、顶在标题栏下方、底距窗口 8**，画布左侧那条 34px 的工具轨（`FlowPanel.tsx:1272`，`left-3`，装着框选/平移、剪切、菜单、左右键互换）**跟着让到面板右侧**：`translate(268px, -50%)`，120ms 同一条缓动。开面板时它才是主角，所以让位的是轨而不是面板（早先反过来做过，面板被推到 54，屏幕上等于白让了一条空的左边）。③ 落地：`clampPanelPosition` 加 `side`/`offset`（ChartPanel 不传即不变），`FlowPanel` 收一个 `commandPanelInset`，由 `App` 用 `COMMAND_PANEL_WIDTH + COMMAND_PANEL_INSET` 算出来传下去。

**补连续性的三件事**（按钮在右、面板在左，需要说明"它是从哪来的"）：

1. 入口按钮保持打开态下划线（`OPEN_UNDERLINE`，与设置/日志同款）；
2. 打开时 120ms `cubic-bezier(0.2, 0, 0, 1)` 淡入 + 从左侧 8px 位移（不是缩放、不是弹跳）；
3. 关掉面板只要 `Esc`、✕ 或菜单栏那个按钮——它不开在屏幕中央，就不会出现"关不掉/找不到"的情况。

**一条已知张力**：800 高窗口里 540（面板）+ 260（日志抽屉）+ 36（标题栏）放不下。日志开着时面板会压住抽屉上半截——两者都是浮层，且命令面板是短暂停留，本稿接受这个重叠，**不做**「打开面板自动收起日志」的联动（那会打断正在看日志的人）。

## 4. 结构

```
┌──────────────────────────────────┐
│ 命令  [ 搜索操作名或描述 ]   x   │ 44  头部：标题 · 搜索 · 关闭（不可拖）
├──────────────────────────────────┤
│ 01 探查                        7 │ 26  分组头吸顶（序号 + 名称 + 计数）
│ view                          ?  │ 40  第一行：等宽命令名
│ 预览 CSV 文件                    │     第二行：中文描述
│ …                                │     （61 项，单列）
├──────────────────────────────────┤
│ 共 61 个操作        ↑ ↓ ⏎ esc    │ 34  底栏：计数 · 键帽
└──────────────────────────────────┘
```

- **头部**：标题「命令」（沿用 `commandPanel` 文案）、搜索框、关闭。**头部不可拖**：位置固定（左缘 8、垂直居中），窗口缩放时重新居中，没有 `dockState`。
- **单列**：分组头吸顶（`position: sticky; top: 0`，底部 1px 细线）+ 一行一个操作。没有左栏目录条——14 个分类靠吸顶头导航，省下的 112px 还给宽度。
- **高度**：`36 + 4` 起、窗口底 − 4 止（`MIN_HEIGHT 280` 兜底），窗口缩放时重算；不做垂直居中。滚动容器用共享的 `ScrollArea`（Radix，与 Ctrl K 面板、设置页同一条 10px 细滚动条），右内边距留 12px 给这条覆盖式滚动条，免得它压住行尾的 `?`。
- **行（40px，两行）**：第一行命令名（等宽 11.5 / 行高 16 / `--fg`），第二行描述（11 / `--muted-fg` / 单行截断）；行尾**常驻**的 `?`（16px 可点区域、弱色，与命令名同一条基线）。名与描述上下排开之后，命令名不再需要 100px 固定列，**面板宽度从 520 收到 380**。
- **底栏**：左「共 61 个操作 · 插件 2」（搜索时「命中 n / 61」），右键位键帽。

## 5. 颜色与状态（一种信号，一处强调）

| 状态 | 写法 |

## 7. 搜索

- 匹配范围：命令名 + 中文描述 + 分类中文短名 + 分类英文名（现状只匹 `name`/`description`/`category`，中文描述没进匹配，中文搜不到 —— 顺带修掉）。
- 空格分词按 AND；中文按子串。
- **命中分类名 = 整组展示**（分组头显示 `3/3`），因为"搜分类"是浏览意图，不是精确查找。
- 空态给三个真能搜到的例子（`去重` / `金额` / `pivot`），而不是"换个词试试"。
- 保留 150ms 防抖与 `↑↓`/`⏎`/`Esc` 语义；`enter` 的索引改按"当前可见行"取（现状用 `visibleCommands[activeIndex]`，重排后跨分组会错位）。

## 11. 验收

1. 1200×800 首次打开：面板 x=8–268，**顶部贴标题栏下方（y=40）、底部距窗口 4（y=796）**，画布工具轨滑到 280–314 且完整可点。**拖不动**（没有 grab 光标）；窗口缩放后两端跟着走。

3. 搜「去重」：只剩 `dedup` 所在组（组头 `3/3`），底栏「命中 3 / 61」。

5. 暗色：行底与面板同色、吸顶头下沿细线可见、命令名对比 ≥ 4.5:1。
6. 位置：任意窗口尺寸下都是 x=8、y=40、高度 = 窗口高 − 44；**按住头部拖不动**（没有 grab 光标、没有位移），窗口从 800 拉到 1100 高时高度跟着长。关面板后工具轨滑回 12。

2. **首步提示沿用 `onboardingPanelHint` 原文**（027 的既有文案："选中第一个操作后, 它会直接对输入数据生效…"），没有改成原型里那句新文案——它已经在别处被引用，改文案会把 027 的验收点一起动掉。
3. **`Shift+Enter` 打开当前行的帮助**：原型只画了行尾 `?`，键盘用户没有入口（该按钮 `tabIndex={-1}` 以保住不变量「Tab 不进 61 行」）。原型 footer 没写这一条，避免底栏堆字。
4. **`/` 聚焦搜索没做**：原型里画了键帽，实现里删掉了（设计 040 也把 `/` 留成开放问题）。要做需和设置页一起上。
5. **列表语义**：`role="listbox"` + `tabIndex={0}` + `aria-activedescendant`，行是 `role="option"`，分组是 `role="group"`（原型是纯 div）。
6. ~~拖动坐标改为 state~~ → 同轮直接**删掉拖动**（见第 12 条）。
7. **`event.target instanceof Node` 守卫**：`fireEvent.keyDown(window)` 会把 `window` 当 target，`contains` 会抛错（测试踩到）。
8. **行改两行 + 面板收窄（2026-11-22 二轮）**：用户要求「命令和描述改两行，减少命令的 width」。行从 `30px / 列 100+1fr+16` 改成 `40px / 列 1fr+16`，命令名与描述上下排（11.5 mono / 11 sans，间距 1px），`?` 与命令名同基线（`self-start mt-[5px]`）；面板 520→**380**、左栏 140→**112**（左栏字号 11.5→11，好让「排序去重」四个字不截断）。代价是首屏行数 15→11，换来 140px 宽度。
9. **默认位从 24 挪到 54（同日四轮；后被第 13 条取代）**：用户指出「展开命令面板时画布工具轨被盖住」。根因是面板默认 x=24 与工具轨（12–46）重叠 22px。工具轨是画布地标、面板是临时浮层，所以面板让位而非挪轨：`DOCK_OFFSET = 54`（12 + 34 + 8）。**只改默认值得不到的事**：用户手动拖到左边仍可覆盖工具轨——这是他的选择，不拦。
10. **滚动容器换 `ScrollArea`（同日三轮）**：`overflow-y-auto` 的裸 div → `<ScrollArea ref={listRef} hideHorizontalScrollbar blockContent viewportClassName="pl-1.5 pr-3 pb-1.5">`，与 Ctrl K / 设置页同一条滚动条（Windows 原生条又宽又深，是它最难看的一处）。三处细节：① `ref` 落在 Radix Root 上，`useScrollSpy` 自己会往下找 `[data-radix-scroll-area-viewport]`，所以滚动联动不用改；② `blockContent` 必须开，否则 Radix 内层 `display:table` 会把行撑到最宽子元素的 min-content；③ 右侧多留 6px（`pr-3`）给覆盖式滚动条。**验证**：headless 的 `--virtual-time-budget` 会饿死 `requestAnimationFrame`（实测 `frames 0`），滚动联动必须在真帧下验——用 CDP 驱动 `viewport.scrollTop = 900` 后读到左栏从 `01 探查` 变成 `04 列操作`、吸顶头偏移 0。
11. **收窄的边界**：260 时描述列 **202px**、61 条一条都不截断（这条线是从 201px 那档量出来的）。再往下就得让描述折行或缩小字号，而不是继续调数字。
12. **删掉拖动 + 去掉坐标记忆（2026-11-22 五轮）**：用户反馈「还是挡住了」——根因是 `dockState` 存在会话里，上次拖到 24 的位置被持久化、覆盖了新的默认 54。既然不需要拖，就直接把状态删干净：`dockState` / `onDockChange` 两个 prop 与 `App.tsx` 的传参一并移除，位置 = `clampPanelPosition(undefined, DOCK_OPTIONS)`，只在 `resize` 时重算。**教训**：给浮层"记住位置"是隐性契约——默认值改了它也不会生效，除非用户双击复位或清会话。固定用途的面板就别给位置状态。
13. **工具轨让位、面板贴左（2026-11-22 六轮）**：用户要求「命令 dialog 在最左边，工具条在它的右边」。于是把第 9 条的结论反过来：面板 `DOCK_OFFSET` 54→**8**（贴窗），`FlowPanel` 新增 `commandPanelInset`，把轨从 `left:12` 用 `translate(panelWidth + inset, -50%)` 推到 **400**，`transition-transform 120ms` 同一条缓动（用 transform 而不是 `left`，避免布局动画）。`HomeView` 只做透传；`App` 用 `CommandList` 导出的 `COMMAND_PANEL_WIDTH` / `COMMAND_PANEL_INSET` 算宽度，避免常量散落。**实测**：`panel 8–388 | rail 400–434 | overlap no`。
14. **删掉左栏目录条（2026-11-22 七轮）**：用户指着左栏说「这部分还是删除比较好，width 可以再减少一些」。删掉 `CommandRail.tsx`（112px）+ 14 条 i18n 短名键里只留分组头需要的三个、`useScrollSpy`（没有高亮目标了）与 `jumpTo`；面板 380→**300**，描述列反而从 201px 涨到 **242px**（省下的 112px 全还给内容），首屏行数不变（11），底栏去掉「插件 2」与键帽文字才放得下。原型同步把「备选 B/C」整帧换成**否决记录**（左栏 / 折叠 / 卡片三条，附否决理由）。
15. **改成「顶到标题栏下方、底贴窗口」+ 再收到 260（2026-11-22 八轮）**：用户要求「height 底部靠近窗口底部、顶部在 tab 栏下方，width 再窄一点」。高度不再写死 540，改成 `y = 36 + 4`、`height = innerHeight − y − 4`（`MIN_HEIGHT 280` 兜底），窗口缩放重算；宽度 300→**260**（描述列 202px，仍 0 截断）。**顺带把 `panelDock` 的 `side`/`offset` 回滚了**——面板不再走 clamp（位置是算出来的固定盒子），留着就是死 API。
