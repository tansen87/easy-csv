## 1. 结论

**值得做，但只做薄的一层：一本记录真实产出的账，不做游戏层。**

- 做：本次结算行（行数 / 步数 / 耗时）、累计读数（常驻右下角）、刻痕里程碑（跨过整数时确认一次）、历程面板（累计 + 近 8 周 + 刻痕）。
- 不做：积分、等级、经验值、连续登录 / 断签、每日任务、排行榜、虚拟货币、抽奖、全屏礼花。

理由有三条:

1. **这个产品的正反馈已经存在，只是没有被看见。** 用户真正关心的是「这次清了多少行、比上次快没快」。把它记下来，比另造一套奖励更直接。
2. **外奖励会挤掉内在动机。** 一旦给动作标价（XP、金币），用户会挑「性价比高」的动作（空跑、反复导出）而不是把活干完；在工作工具里，这是净损失。
3. **断签机制与产品性格冲突。** 这是每天打开干活的桌面工具，不是日记应用。「今天还没打卡」只会制造压力，且和「精确、克制」的界面语言相反。

## 2. 目标与非目标

| | 内容 |
|---|---|
| 目标 | 每次成功运行后，用户能在**不离开当前画面**的情况下知道这次产出多少；累计数字随时间增长；跨过整数时有一个值得记住的时刻 |
| 目标 | 零新增阻塞：不弹模态、不抢焦点、不影响运行与结果查看；可一键关闭并清空 |
| 非目标 | 提高日活、留存、使用时长；不做任何形式的排行榜、社交分享、账号体系 |
| 非目标 | 不估算「节省了多少时间」——换手算的耗时无法核实，写出来就是编数字 |

## 3. 三层设计

| 层 | 出现位置 | 内容 | 生命周期 |
|---|---|---|---|
| 结算行 | 现有运行读数末尾（`HomeView` tab 行右端，`分支 3/3 · 完成 · 2.1 s` 后面） | `本次 24,318 行 · 3 步` | 跟随运行读数，几秒后一起消失 |
| 累计读数 | 画布右下角常驻按钮 | `账本 312,904 行 ›` | 常驻；点击打开历程面板 |
| 里程碑卡 | 右下角，累计读数上方 | 一道刻痕 + `100,000 行` + 一句副文案 + `查看历程` | 一次只显示一张，5 秒自动消失，可手动关 |
| 历程面板 | ViewDock 第五个面板（`Alt 5`） | 累计行数、运行次数 / 文件数 / 命令种类、近 8 周柱图、本周节奏、刻痕列表、清空 | 用户主动打开 |

选择理由（对应原型 02 节的三方向）:

- **A 结算行** 是零成本方案:不新增界面，只把本次事实接在已有读数上。
- **B 刻痕里程碑** 提供稀有确认:一年只有十几个时刻，足够「强」，又不会每天出现。
- **C 游戏层** 只作为反例出现在原型里，不进入实现。

## 4. 画面与交互细节

### 4.1 结算行

```
分支 3/3  [完成 · 汇总]  │  2.1 s  │  本次 24,318 行 · 3 步
```

- 追加在 `HomeView` 运行读数的 `RunTimer` 之后，沿用等宽数字与分隔线。
- 行数取本次运行**最后一个结果节点**的 `totalRows`；步数取本次实际执行的步骤数。
- 运行读数本来就会在完成几秒后淡出（`runReadoutDismissed`），结算行跟随，不额外延长。
- 失败 / 取消不显示结算行。

### 4.2 累计读数与里程碑卡

- 右下角按钮尺寸与现有画布浮层一致（高 26，圆角 7，1px 描边），只有一枚刻痕图标、一个词和等宽数字，不用彩色胶囊。
- 里程碑卡宽 306，右下角浮起 4px 淡入，`5 s` 自动消失；右上角可立即关闭。多枚同时达成时排队，一次一张。
- 数字从旧值滚到新值 240ms，等宽不跳位；刻痕按书写方向描边 180ms；`prefers-reduced-motion` 下全部直接显示。
- 不做音效、不做礼花、不做全屏遮罩、不做「恭喜 / 太棒了 / 解锁成就」类文案。

### 4.3 历程面板

- 新增 `ViewPanelId: "ledger"`，加入 `VIEW_PANELS`（图标用 `NotebookPen` 或 `BookOpen`，快捷键 `5`），与 045 的停靠区规则一致。
- 内容自上而下: 大数字（累计行数）→ 三个统计（运行次数 / 文件数 / 命令种类）→ 近 8 周柱图 + 本周 7 个圆点 → 刻痕列表（已解锁带日期，未解锁带阈值）→ 页脚「只记数字，不记文件名与路径」+「清空…」。
- 空态: 面板显示「第一次运行后，这里开始记账」，不显示柱子，不显示 0 的大数字。
- 柱图只有当前周用品牌色，其余用中性色；不做坐标轴、不做 tooltip。

### 4.4 设置

在「通用」分组新增一行:

- 标题「记录使用账本」，开关默认开。
- 说明「只在本机记录累计行数、运行次数与用过的命令名；不记录文件名、路径和列名，也不会上传。」
- 下方次级操作「清空账本」（二次确认）、「导出账本 JSON」。
- 关闭后: 结算行、累计读数、历程入口全部隐藏，停止写入；已有数据保留，重新打开后从断点继续。

## 5. 数据口径

| 项 | 口径 |
|---|---|
| 行数 | 本次运行最后一个结果节点的 `ResultPreview.totalRows`；多分支只记主链路终点，不累加中间步骤。取不到记 0，不估算 |
| 运行次数 | 一次成功执行记 1（全量 / 前缀 / 从此步运行都算）；失败与取消不记 |
| 耗时 | 复用 `RunSession.durationMs`，与执行历史同源 |
| 文件数 | 本次运行里 `output` 步骤写出的文件数累加；**不保存路径**，因此不做跨运行去重 |
| 命令种类 | 成功运行中出现过的 `command.name` 去重集合 |
| 去重 | 以 `runId` 为键，同一 run 只记一次；刷新、重放、切标签页都不重复 |
| 并发 | 多个标签页并发运行各记各的，累计写入同一份账本；读改写一次完成 |
| 里程碑 | 只在跨过阈值的那一次触发；已解锁存时间戳，永不回退；`first-run` 只入账不弹卡 |

## 6. 存储

`localStorage` key: `easy-csv:ledger:v1`

```ts
interface LedgerState {
  v: 1;
  totals: { rows: number; runs: number; files: number; ms: number };
  /** 成功运行里出现过的命令名（去重） */
  commands: string[];
  /** 里程碑 id → 首次达成时间（ISO） */
  milestones: Record<string, string>;
  /** 最近 90 天的按日分桶 */
  days: Record<string, { rows: number; runs: number }>;
  /** 防重复的最后一条 runId */
  lastRunId: string | null;
}
```

- 写入点: 执行成功分支（`useExecution` 的完成处），与结果预览、日志写入同一处，避免遗漏分支。
- `days` 每次写入裁剪到 90 天；`milestones` 只增不减。
- 清空 = 删除该 key，不动任何管道、结果、日志、设置。

| id | 名称 | 阈值 |
|---|---|---|

| `rows-10k` | 一万行 | 10,000 |

| `rows-1m` | 百万行 | 1,000,000 |
| `rows-10m` | 千万行 | 10,000,000 |
| `runs-10` | 十次运行 | 10 |
| `runs-100` | 百次运行 | 100 |

| `commands-10` | 十种命令 | 用到第 10 种 |
| `template-first` | 第一次用模板 | 应用任意模板 |
| `step-run-first` | 第一次从此步运行 | 使用 078 的入口 |

## 8. 风险与边界

| 风险 | 处理 |
|---|---|
| 数字制造压力 | 只展示累计，不做连续天数、不设每日目标、不设进度环 |
| 变成「刷数据」 | 只记成功运行；同一 `runId` 只算一次；不记空跑与失败 |
| 隐私顾虑 | 只存数字与命令名，不存文件名、路径、列名；不联网；可关闭、可清空、可导出 |
| 机制膨胀 | 一旦要加分享、称号、商店，就超出本设计范围，需要重新回答「有没有必要」 |

## 9. 验收标准

- [ ] 一次成功运行后，运行读数出现「本次 N 行 · N 步」，几秒后随读数消失；失败与取消没有。
- [ ] 累计读数常驻右下角，点击打开历程面板；关闭账本后三处入口同时消失。
- [ ] 跨过 100,000 行时只弹一张卡，5 秒消失；再次超过 100,000 不会重复触发。
- [ ] 历程面板数字、柱图、刻痕与 localStorage 一致；清空后回到空态。
- [ ] 暗色主题与 `prefers-reduced-motion` 下表现正确。

与提案的四处偏差:

1. **文件数**按写出次数累加，不存路径，因此不做跨运行去重 —— 隐私约束优先于统计精度。
2. **清空账本**坐在「设置 › 维护」的危险项里（与清空执行历史同组），面板底部只留隐私说明；未做面板内清空与导出 JSON。
3. **第一个 / 十个管道**按「保存脚本成功」的次数计，而不是统计管道库条目（项目里没有稳定的管道总数来源）。
4. 结算行跟随现有运行读数：完成态显示 2.5 s 后与读数一起消失，不额外延长。
