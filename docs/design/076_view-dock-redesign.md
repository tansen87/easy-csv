> 状态: **已实现(2026-11-24,采用方案 A)**;实施记录与偏差见 §9

## 1. 现状审计

> 决策:评审后**采用方案 A(单槽 + 页签栏)**。B、C 保留为备选记录,不再实施。

用户的原话是「点多个时会覆盖」。这不是手感问题,是四个开关共用一套坐标。

|---|---|---|---|

## 2. 方向(unslop 五条)

- **产品**:桌面 CSV 管道工具。把 xan 的 59 条命令串成一条管道,一边看数据一边改管道。
- **性格**:精确、克制、有点旧账房的耐心(不是"现代简洁")。
- **世界**:账本与索引卡——表格线、索引编号、插在页间的页签。这种工具的用户盯着数字看一天,界面要像一张好账页。
- **时刻**:停靠区本身。概览的完整度标尺、血缘由源到结果的细线,是整屏唯一有颜色与厚度的地方;其余全是灰线与墨色。
- **签名**:`01–04` 索引编号 + 页签凸耳。收起的列不是消失,而是像书脊一样立在页间。

一句话:面板是**页**,不是**窗**。页可以并排,但不会互相盖。

## 3. 三个方案

### 方案 A · 单槽 + 页签栏 → [原型 01](prototypes/076/01-view-dock-single-slot.html)

- **结构**:停靠区永远一列 320(可拖 280–420),右缘一条 40px 页签栏;四项各占 30×38,只有 16px 图标,激活项品牌 12% 底、墨色转品牌。
- **菜单**:改成单选(`menuitemradio`),选中态只靠一行浅底,行首不画勾;菜单只有四项。`Alt 1–4` 直接切页。
- **宽度账**:320 + 40 = 360 恒定;1200 窗口里画布 840。
- **代价**:一次只能看一个。想对照"缺失值分布"和"哪列在血缘里活下来"要来回切。

### 方案 B · 双列 + 书脊 → [原型 02](prototypes/076/02-view-dock-two-column.html)**(推荐)**

- **结构**:停靠区是一排真实的列,顺序固定 **概览 → 版本 → 血缘 → 变量**(与菜单顺序一致)。每列三态:`关`(0)、`书脊`(44)、`展开`(320)。收起时它**留在原位**只改宽度,别的列一动不动。
- **最多两列**。打开第三个时,把**最久没用**的那一列收成书脊——不是你刚点的那一列,所以刚点的永远不会消失。
- **书脊**:44px,顶部 16px 图标,竖排 12px 标题居中,底部 9px 序号;悬停品牌 6% 底。竖排标题就是账本的书脊,扫一眼知道收着哪几本——比纯图标条少一次 tooltip。
- **宽度预算**:画布 ≥ 440。`窗口 − AI − Σ列` 不足时继续收列(按 LRU),全收完仍不足就保持 44 书脊。1200 窗口 + AI 打开时:360 + 320 + 44 = 724,画布 476 ✓。
- **菜单**:四项仍是复选,但右端写出位置 `展开 / 书脊 / 关`,勾只表示"在停靠区里"。
- **代价**:多一个概念(书脊),要一次解释;宽度会自己变,收列时需要一行 toast("版本控制收进书脊");实现最大。

### 方案 C · 一体检查器 → [原型 03](prototypes/076/03-view-dock-inspector.html)

- **结构**:四个面板合并成一个 360px 的检查器,头部是分段控件 `01 概览 / 02 版本 / 03 血缘 / 04 变量`,分段下是这一页的事实行(行数列数 / 版本数 / 源列数 / 待填数),页内动作挂在事实行右端。
- **菜单**:四项都是"打开并把检查器翻到这一页",`menuitemradio`,勾 = 当前页,右端显示该页关键数字。另外把"待填变量数"做成**运行按钮上的琥珀数字**,不必打开 04 也知道会被拦。
- **宽度账**:360,与 AI 同宽;1200 窗口画布 840。
- **代价**:治的是语法不是坐标——面板不再是可并存的窗口;页内要二级头,垂直空间多花 40px;四页语义不同(看/存/改),壳给不了统一承诺。

### 对比

| 维度 | A 单槽 | B 双列 + 书脊 | C 检查器 |
|---|---|---|---|
| 还能不能"点多个" | 不能,但不会装作能 | **能,最多两列** | 不能 |
| 覆盖是否可能 | 不可能 | 不可能 | 不可能 |
| 宽度是否可算 | 恒定 | 有预算规则,可算 | 恒定 |
| 新概念 | 页签栏(一个) | 书脊 + LRU 收列(两个) | 分段检查器(一个) |
| 菜单语义 | 单选 | 复选 + 位置词 | 单选 |
| 实现成本 | 小 | 大 | 中 |
| 面板头部 | 保留各自 | 统一成 `DockHeader` | 合并成一个 |

**推荐 B**。理由是它直接兑现用户的期待:点第二个是为了同时看,不是为了换一个;而"第三个收进书脊"让"被收起"仍然可见,不会重演今天"点了就没了"的困惑。A 是它的窄窗退化形态(B 在预算不足时行为与 A 一致),C 适合将来真的想收掉"四个入口"时再做。

## 4. 推荐落地:两阶段

不让一个 bug 的修复绑在最大的重写上。

### 阶段 1 · 先把"覆盖"和"越界"消灭(可独立发布)

1. 新增 `src/hooks/useViewDock.ts`:一个 `Record<ViewPanelId, "closed" | "spine" | "open">` + LRU 列表,替代 5 个布尔;导出 `slots` 与 `dockWidth`。
2. 停靠区从四个绝对定位的 div 改成 `HomeView` 里的一段 flex 行:画布 `flex:1`,停靠列 `flex:none`。这样 `panelRightInset` 自然消失,标签页带/读数/工具轨/日志不会再伸到面板下(修审计 #6)。
3. 阶段 1 先只做两态(`open` / `closed`)与"最多两列,第三个按 LRU 关闭",并给一行 toast。此时已彻底无覆盖、无越界。
4. 四列共用一个宽度 `<DockColumns>` 管理拖拽(280–420),不再各写 320。

### 阶段 2 · 书脊与菜单

5. 加第三态 `spine`:宽度 44,竖排标题,点击换回展开;收列时 toast 一次(同一会话只提示一次)。
6. 宽度预算守门:开列 / 开 AI / 缩窗口三处都走同一个 `applyBudget()`,保证画布 ≥ 440。
7. 菜单右端加位置词;`查看` 触发器的下划线改为"停靠区里有任何列"(`anyCollapsedPanelOpen` 换成 `dock.length > 0`)。
8. 统一列头 `DockHeader`(序号、标题、页内动作、收起、关闭)。

## 7. 不做的事

- **不做浮窗**。把面板改成可拖动浮窗能"不覆盖",但会同时带来遮挡、层级、位置记忆三个新问题,与 071 把日志从浮窗收到抽屉的方向相反。
- **不做四个面板的自动折叠面板组**(accordion)。四个都开时窗口里只剩四条 36px 的条,等于把内容藏起来。
- **不改画布手势**、不改 AI 面板内部、不改面板数据逻辑。
- **不记忆跨会话**。停靠状态只活在本次会话;要记忆时再说(会话快照里已经有 `panelStates` 的先例,可后续接入)。
- **不加"未连接/未打开"类提示**。收进书脊不是错误状态,不加警示色、不加呼吸动画。

## 9. 实施记录(方案 A,2026-11-24)

### 9.1 落地形态

一个槽:`useViewDock` 持有 `activePanel` 与 `panelWidth`,导出 `dockWidth = activePanel ? panelWidth + 40 : 0`。`ViewDock` 是一段真实的 flex 列(面板 + 40px 页签栏),不再是 `absolute` 覆盖层;`mt-9` 从顶栏下方开始,与标签页带同一水平线。

| 项 | 实现 |
|---|---|
| 单选 | 查看菜单四项 `role="menuitemradio"`,`aria-checked` = `activePanel`,但**行首不画勾**——选中只由 `bg-primary/10` 的一行浅底表示;再点同一项 = 关闭。菜单里没有第五项,也没有 `Alt 0` |
| 页签栏 | 40px,四项 30×38,只有 16px 图标(不带序号),激活 = 品牌 12% 底 + 品牌墨色;`aria-pressed` |
| 快捷键 | `Alt 1–4` 开/关对应面板 |
| 宽度 | 280–420,拖左缘 6px 热区;双击复位 320;四面板共用 |
| 切换动效 | 120ms 淡入(`.dock-panel-in`),不动宽度,尊重 `prefers-reduced-motion` |
| 单一宽度来源 | `dockWidth` 同时给主区域预留、日志抽屉 `rightInset`、图表胶囊 `capsuleRight` |
| 统一头部 | `DockHeader`(标题 + 事实行 + 页内动作 + 关闭),四面板共用 |

### 9.3 与原型的两处偏差

1. **菜单行由 App 构建**:`components/` 不允许 import `modules/`(019 §5.2),所以 `MainMenu` 收 `viewPanels: ViewPanelMenuItem[]`(id / 已本地化文案 / 键帽 / 是否禁用),自己不再认识面板。菜单行不带序号,也没有底部说明行。
2. **页签栏底部没有额外关闭按钮**:与原型一致,关闭只有三个入口 —— 面板头 ×、菜单「关闭停靠区」、`Alt 0`。
3. **没有序号**:最初面板头与页签栏都带 `01`–`04`,后来整条去掉(见 §9.4),`DockHeader` 与注册表都不再有 `index`。

### 9.4 减法三则(2026-11-24 追加)

**去掉勾。** 查看菜单里的四行原来复用 `Check` 图标表达"当前面板",选中行既有一行浅底、又有一个勾,两种信号说同一件事。勾连同它的占位一起删掉(`Check` 也从 `MainMenu` 的 import 里移除),选中态只留底色;`aria-checked` 保留,读屏仍知道哪一项是当前面板。

**去掉索引编号。** 面板头的 `01`、页签栏图标下的 `01`–`04` 全部删除:`DockHeader` 不再收 `index`,`viewPanels.ts` 的注册表也不再存序号,页签栏每格只剩一个 16px 图标(`grid place-items-center`)。序号在菜单里已经删过一次,这是它在界面上最后的两处。

**去掉第五项。** 分隔线与「关闭停靠区」整段删除,`Alt 0` 也一并去掉——`Alt + 数字` 现在只表示"切到第 N 个面板",不再兼职"全关"。关闭仍有三个入口:面板头 ×、再点一次当前菜单项、点一下已激活的页签栏图标。`onCloseViewDock` 这个 prop、`viewDockClose` 这条文案(中/英/类型)与 `useViewDock` 里的 `Alt 0` 分支全部移除,`closeDock` 仍被四个面板的 × 使用。

### 9.5 滚动区统一(2026-11-24 追加)

停靠区四个面板原来只有「数据概览」用 `ScrollArea`,其余三个是原生 `overflow-y-auto`——同一个停靠列里两种滚动条。现已全部统一:

| 面板 | 位置 | 处理 |
|---|---|---|
| 数据概览 | 列清单 | 原本就是 `ScrollArea` |
| 版本控制 | 保存版本表单 / 空状态 / 无匹配 / 版本列表 | 4 处全部换成 `ScrollArea`(`blockContent` + `hideHorizontalScrollbar`),内边距下沉到内层 div |
| 数据血缘 | 主体 | 换成 `ScrollArea`,`ref` 与 `onKeyDown` 直接挂在根上(键盘上下移动仍靠 `querySelectorAll("[data-lineage-row]")`) |
| 管道变量 | 变量组 | 换成 `ScrollArea`,首行间距走 `viewportClassName="pt-1"` |

统一参数:`blockContent`(Radix 内部 `display:table` 改回 block,网格行才能撑满宽度)、`hideHorizontalScrollbar`(只有纵向内容)。滚动条沿用既有默认 `type="hover"`——与帮助中心、AI 面板、数据概览一致,鼠标进入面板才浮出细滑块。
