# 顶栏右侧图标区重设计（MainMenu 右侧按钮组）

> 基于 `src/components/menu/MainMenu.tsx`（410 行全文实测）与顶栏截图（2026-09-05）识别的布局优化点。
> 与既有文档分工：
> - 对话框体系 / 面板停靠 / token / 键盘可达性 → `007_ui-design-optimization.md`（本文 T6 仅引用其结论，不重复展开）
> - 本文只覆盖一件事：**顶栏右侧 10 个图标按钮的信息架构与视觉重排**。

---

## 1. 现状基线（实测）

右侧按钮区为单个 `flex gap-1` 容器内 10 个纯图标按钮，全部同级、无分隔线：

| # | 图标（lucide） | 功能 | 类型 | 可见性 | 使用频率（推断） |
|---|---------------|------|------|--------|----------------|
| 1 | `PackageOpen` | 打开命令面板 | 命令入口 | 恒显 | 高 |
| 2 | `CommandIcon` | 命令列表面板开关 | 面板 toggle | 恒显 | 高 |
| 3 | `FileText` | 日志面板开关 | 面板 toggle | 恒显 | 高（执行期） |
| 4 | `BarChart3` | 数据画像开关 | 面板 toggle | 仅 `hasInputFile` | 中 |
| 5 | `GitBranch` | 版本历史开关 | 面板 toggle | 恒显 | 低 |
| 6 | `GitMerge` | 数据血缘开关 | 面板 toggle | 恒显 | 低 |
| 7 | `Bot` | AI 助手开关 | 面板 toggle | 恒显 | 高 |
| 8 | `CloudDownload`/`RefreshCw` | 检查更新 | 全局动作 | 恒显 | 极低 |
| 9 | `MessageCircleQuestionMark` | 帮助 | 全局动作 | 恒显 | 低 |
| 10 | `Settings` | 设置 | 全局动作 | 恒显 | 低 |

### 问题信号

- **P0 · 无信息架构**：10 个按钮分属三类语义（命令入口 / 面板开关 / 全局动作），却以完全相同的尺寸、颜色、间距一字排开，用户只能靠 tooltip 逐个悬停辨认——这正是截图"看起来杂乱"的根源。
- **P0 · 图标语义冲突/近似**：
  - 日志用 `FileText`，与左侧 File 菜单图标及"打开新标签页"菜单项 `FileText` 撞车；
  - `GitBranch`（版本历史）与 `GitMerge`（数据血缘）相邻放置，形态高度近似，极易误点；
  - `PackageOpen`（命令面板）语义指向不明，与 `CommandIcon`（命令列表）放在一起时两个"命令"图标相邻但互不相干。
- **P1 · 激活态不可辨**：6 个面板 toggle 的选中态是 `bg-primary/10`，与 hover 态 `hover:bg-primary/10` 完全相同——不悬停对比就无法判断哪个面板已打开。
- **P1 · 低频动作占据高频区位**：「检查更新」是极低频动作，却永久占据顶栏最贵的视觉资源；它唯一的信息价值（有新版本）反而因为常驻而不可见。
- **P2 · 左右风格断裂**：左侧按钮"图标+文字"，右侧纯图标；同类工具栏内两种密度并存。

---

## 2. 设计原则

1. **分组先于删减**：10 个图标不必全删，先按语义分区、用分隔线建立结构，杂乱感即消除大半；
2. **高频直出、低频收纳**：执行流程中反复操作的面板保留直出开关，分析型/回顾型面板收进统一菜单；
3. **激活态必须可见**：toggle 的"开"与"关"在 1 米外可区分；
4. **一个图标一个语义**：全应用范围内图标不与左侧菜单冲突、不互相近似；
5. **状态信息徽标化**：低频动作（更新、日志错误）用红点/徽标表达"有情况"，而非靠常驻占位。

## 3. 重设计方案

### T1. 三区分组布局（P0）

右侧改为三组，组间用 1px 竖分隔线：

```
┌────────────────────────────────────────────────────────────────────────────┐
│  File   ↶ ↷   ▶ Execute          ⌘K │ ▦  ⌗  🤖 │ ◔ 更多面板      ? │ ⚙   │
│ ←左侧：菜单/编辑/执行（现状不变）→   ├─ 命令入口 ─┴─ 面板区 ─┴─ 收纳 ─┴ 全局 ─┤
└────────────────────────────────────────────────────────────────────────────┘
```

| 分区 | 内容 | 说明 |
|------|------|------|
| 命令入口 | ⌘K（命令面板） | 唯一保留，图标改为 `Command`（与快捷键 Ctrl+K 心智一致） |
| 面板区（直出） | 命令列表、日志、AI | 执行流程高频三件套（见 T2 取舍） |
| 面板区（收纳） | 「更多面板」下拉 | 数据画像 / 版本历史 / 数据血缘，见 T3 |
| 全局 | ? 帮助菜单、⚙ 设置 | 更新检查并入帮助菜单，见 T4 |

分隔线样式：`<div className="w-px h-4 bg-border mx-1" />`，与现有 `rounded-md` 体系一致。

### T2. 高频面板直出（P0，方案取舍）

**推荐方案 A**：仅保留命令列表、日志、AI 三个直出开关，其余收进菜单。

理由：
- 命令列表（构建管道）、日志（看执行结果）、AI（生成管道）是"编辑→执行→查看"主循环的组成部分，每次会话都会触碰；
- 数据画像、版本历史、数据血缘是**分析/回顾型**动作，典型使用是打开→看一眼→关闭，常驻开关的收益低于其视觉成本；
- 直出开关从 6 → 3，右键图标区密度减半。

**备选方案 B**：全部 6 个面板收进单一「面板」菜单，直出区只剩 ⌘K + ？+ ⚙（最极简，但 AI/日志多一次点击）。若后续实测用户高频使用画像/版本功能，可再从菜单提升 1 个为直出。

### T3. 「更多面板」下拉菜单（P0）

新增 `PanelMenu` 下拉（复用项目内 dropdown 组件，样式对齐 File 菜单）：

- 菜单项为 checkbox 行：数据画像（`BarChart3`）、版本历史（`GitBranch`）、数据血缘（`GitMerge`）；
- 每项右侧标注快捷键（与 F2 快捷键规划同步登记进冲突表）；
- 勾选即开对应面板，再点取消；菜单触发按钮在任一面板开启时显示激活态；
- 数据画像保持现有 `hasInputFile` 条件逻辑，无输入文件时置灰 + tooltip 说明原因（现状是直接隐藏，导致图标数量不定、肌肉记忆失效——收纳后位置恒定，改善心智模型）。

### T4. 帮助菜单合并低频全局动作（P1）

`?` 改为下拉菜单，收编：

- 检查更新（迁出现有 `CloudDownload` 按钮；检查中发现新版本时 `?` 按钮右上角显示绿点徽标）；
- 帮助中心（现有 HelpDialog）;
- 预留：快捷键速查（配合 007-D4）、关于。

顶栏恒显的全局动作收敛为 `?` 与 `⚙` 两个，`⚙` 保持直出（低频但属于"最后一公里"动作，用户找不到时会焦虑）。

### T5. 激活态与状态徽标（P1）

1. 面板 toggle 激活态与 hover 态分离：
   - hover：`hover:bg-accent/60`
   - 激活：`bg-accent text-foreground` + 按钮底部 2px 指示条（`after:` 伪元素或内嵌 `<span>`），保证不依赖色觉也能区分；
2. 日志面板关闭但执行失败时，日志图标叠加红色圆点徽标（"有新错误"），点击打开后清除；
3. 更新可用时 `?` 菜单触发按钮显示绿点（见 T4）。

### T6. 图标语义修正（P1，随 T1–T3 一并落地）

| 功能 | 现图标 | 建议图标 | 理由 |
|------|--------|----------|------|
| 命令面板 | `PackageOpen` | `Command` | 与 Ctrl+K 心智一致，且与左侧 File 菜单无冲突 |
| 日志面板 | `FileText` | `ScrollText` | 让出 `FileText` 给 File 菜单体系，消除撞车 |
| 命令列表 | `CommandIcon` | `ListTree`（或 `ListOrdered`） | 原图标让渡给命令面板；列表本体用列表形图标 |
| 数据血缘 | `GitMerge` | `Workflow` | 与版本历史 `GitBranch` 拉开形态距离 |
| 版本历史 | `GitBranch` | 保留 | 形态清晰，仅与血缘错开后不再近似 |

### T7. 密度与尺寸 token（P2）

- 图标按钮统一 `h-7 w-7`（现 `px-1.5 py-1.5` 实际高度不一）、图标统一 `h-4 w-4`；
- 组内间距 `gap-0.5`，组间分隔线 `mx-1.5`；
- 该规范并入 `007_ui-design-optimization.md` D3 的 token 白名单，新图标按钮照抄模板而非各自手写。

### T8. 可达性（P1，依赖 007-D4）

- 纯图标按钮的 `aria-label` 现状已全覆盖，重排时保持；
- tooltip 增加快捷键提示（如"命令面板 Ctrl+K"）；
- 「更多面板」菜单与帮助菜单接入统一 Esc 关闭与焦点归还（复用 007-D4 的 `useEscClose` + dialog stack）。

## 4. 重排前后对比

**重排前（10 个同级图标）**：

```
⌗(面板) ⌘(列表) 📄(日志) 📊(画像) 🌿(版本) ⑂(血缘) 🤖(AI) ☁(更新) ?(帮助) ⚙(设置)
```

**重排后（4 组结构 + 6 个恒显图标）**：

```
⌘K │ ⌗  ⌍  🤖 │ ◔▾ │ ? ⚙
命令   高频面板  更多面板  全局
```

恒显图标 10 → 6，新增 2 个下拉菜单；所有功能无删减，仅重排。

## 5. 验收清单

- [ ] 右侧图标区存在至少 3 条语义分隔线，命令/面板/全局三区肉眼可辨；
- [ ] 恒显图标 ≤ 6 个，数据画像/版本历史/数据血缘可从「更多面板」菜单开启，行为与原按钮一致；
- [ ] 无输入文件时「数据画像」菜单项置灰并说明原因（不再隐形消失）；
- [ ] 任一面板开启时，其直出开关或菜单触发按钮有与 hover 不同的激活态（含非颜色线索）；
- [ ] 「检查更新」不再常驻顶栏；有新版本时帮助按钮出现徽标；
- [ ] 日志错误徽标：执行失败且日志面板关闭时出现，打开面板后清除；
- [ ] 新图标映射落地后，`FileText` 不再同时出现于 File 菜单与日志按钮；
- [ ] 所有图标按钮 tooltip 含快捷键（如有）、`aria-label` 全保留、Esc 可关闭新增下拉；
- [ ] 快捷键变更登记进 `KeyboardShortcuts.ts` 冲突表并更新 README。
